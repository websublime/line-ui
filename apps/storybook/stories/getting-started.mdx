# Getting Started

line://ui publishes nine packages under the `@websublime` scope. Three of them ship the design-system CSS, `line-components` ships the components, and `line-genui` is an opt-in package for agent-driven UI. This guide installs the CSS and the components, loads the components from a CDN without a build step, and points to the guide for `line-genui`.

| Package | Holds |
|---|---|
| `@websublime/line-tokens` | The global tokens (CSS) |
| `@websublime/line-colors` | One palette file per hue (CSS) |
| `@websublime/line-themes` | The role mappings, such as accent and gray, the semantic roles and the named aliases (CSS) |
| `@websublime/line-components` | The 20 components, one subpath each |
| `@websublime/line-core` | `LineElement`, the mixins and the state-machine controller the components build on |
| `@websublime/line-icons` | The icon registry and the Lucide and Phosphor resolvers for `<line-icon>` |
| `@websublime/line-genui` | Opt-in. Component descriptors, the A2UI catalogs and the `<line-a2ui-surface>` renderer |
| `@websublime/line-schemas` | Zod schemas and typed lists for the hues, roles, steps and aliases |
| `@websublime/line-utils` | Colour helpers for mixing, tints, shades, alpha and contrast |

## Install

Install the design-system CSS first. Every component reads its colours and sizes from it.

```sh
bun add @websublime/line-tokens @websublime/line-colors @websublime/line-themes
```

Then install the components. `line-components` brings `line-core` with it.

```sh
bun add @websublime/line-components
```

Add `line-icons` when a `<line-icon>` names an icon from a library, such as Lucide or Phosphor.

```sh
bun add @websublime/line-icons
```

### Agent-driven UI

`line-genui` is opt-in. Install it with its two peer dependencies, `line-components` and `line-icons`.

```sh
bun add @websublime/line-genui @websublime/line-components @websublime/line-icons
```

The [Agent-driven UI guide](?path=/docs/agent-driven-ui--docs) covers the catalogs, the descriptors, the frontend tools and `<line-a2ui-surface>`.

## Setup

Import the packages once in your global stylesheet. This minimal setup loads one accent hue, one gray hue and the four semantic hues.

```css
@import '@websublime/line-tokens';
@import '@websublime/line-colors/indigo';
@import '@websublime/line-colors/slate';
@import '@websublime/line-colors/green';   /* success */
@import '@websublime/line-colors/amber';   /* warning */
@import '@websublime/line-colors/red';     /* danger */
@import '@websublime/line-colors/blue';    /* info */
@import '@websublime/line-themes';         /* role mappings + semantics + aliases + defaults */
```

Every hue you reference through `data-accent` or `data-gray` must be imported above. The minimal setup imports `indigo` (the default accent), `slate` (its auto-paired gray) and the four semantic hues. If you set `data-accent="violet"`, add `@import '@websublime/line-colors/violet'`, or the role variables resolve to undefined values.

Then set the accent on the root element.

```html
<html data-accent="indigo">
```

## Hello world

<div data-accent="indigo" style={{ background: 'var(--line-accent-solid)', color: 'var(--line-accent-contrast)' }}>Hello, line://ui</div>

```html
<div data-accent="indigo" style="background: var(--line-accent-solid); color: var(--line-accent-contrast)">Hello, line://ui</div>
```

The `data-accent` attribute picks the accent hue for the element and everything inside it. Change the value to another hue you have imported, such as `violet`, and the same role variables re-theme the element.

## Components

Each component has its own subpath, and importing the subpath defines its element.

```js
import '@websublime/line-components/button';
```

```html
<line-button>Save</line-button>
```

The root entry, `@websublime/line-components`, defines no element. It exports `setIconRegistry`, which hands a `line-icons` registry to every `<line-icon>`.

The 20 subpaths are `alert`, `aspect-ratio`, `avatar`, `avatar-group`, `badge`, `button`, `button-group`, `center`, `chip`, `grid`, `icon`, `icon-button`, `kbd`, `portal`, `presence`, `separator`, `skeleton`, `spinner`, `stack` and `visually-hidden`. Each one has a docs page under Components › Primitives Base in the sidebar.

## CDN

The components also load from a CDN with no build step. Two paths are supported, jsDelivr `+esm` and unpkg raw files. Both cover `line-components` and `line-core`. The design-system CSS from Setup is outside this CDN contract.

The URLs follow three rules on both paths.

- Use full subpath URLs. A bare package URL returns 404 and is not supported.
- Name an exact version in every `@websublime/*` URL, never a range such as `@0.2` and never `@latest`.
- Load each `@websublime/*` package at one version per page. For `line-core`, that version is the one the `line-components` files import, `0.2.3` for `line-components` `0.2.8`.

### jsDelivr `+esm`

The URL form is `https://cdn.jsdelivr.net/npm/@websublime/line-components@0.2.8/<subpath>/+esm`, and the root entry is `@0.2.8/+esm`. The page needs no setup.

```html
<script type="module">
  import { setIconRegistry } from 'https://cdn.jsdelivr.net/npm/@websublime/line-components@0.2.8/+esm';
  import 'https://cdn.jsdelivr.net/npm/@websublime/line-components@0.2.8/button/+esm';
  import 'https://cdn.jsdelivr.net/npm/@websublime/line-components@0.2.8/icon/+esm';
</script>

<line-button>Save</line-button>
```

A page that builds its own elements on `line-core` imports it at the same version the components import.

```js
import { INTERNALS, LineElement } from 'https://cdn.jsdelivr.net/npm/@websublime/line-core@0.2.3/+esm';
import { FormAssociated } from 'https://cdn.jsdelivr.net/npm/@websublime/line-core@0.2.3/mixins/form-associated/+esm';
```

This path has known costs.

- The page loads two copies of `lit-html` and `@lit/reactive-element`.
- Each `+esm` URL carries its own copy of the icon registry module. The copies share one registry through a global symbol, so `setIconRegistry` from the root URL reaches every `<line-icon>`.
- jsDelivr marks the `+esm` endpoint as beta.
