## Part A — Requirements

### Overview

#### Description

`<line-icon>` draws one icon glyph from an icon set the consumer registers, from an SVG file, or from SVG path data (PRD §4.1, `docs/PRD.md:254`). The `name` and `library` attributes ask the consumer's registry for the glyph, `weight` passes the icon weight to the resolver, and the boolean `mirror` flips the glyph in right-to-left layouts (Phase 1 spec §6.C.3 "Decided icon surface"). `src` loads an SVG file, and the `path` property draws path data in a 24 × 24 box (Phase 1 spec §10 SD33). Every SVG string passes a Trusted Types policy, `DOMParser` and an element and attribute allowlist before it enters the shadow root (Phase 1 spec §10 SD91, SD95, SD97). The icon is decorative by default and hides itself from assistive technology. A host `aria-label` or `aria-labelledby` turns it into an `img` with that name (decision D1). It takes the text colour through `currentColor` and its size from `--line-icon-size`, which defaults to `1em` (decision D2). A missing source, an unknown name or any failed load leaves an empty box of the same size and raises nothing (ARCH §17.2 C8; MANIFESTO Law 9).

#### Use cases

- Put a glyph beside text, such as in a Button `prefix` or `suffix` slot (`docs/specs/0002-button.md:53`).
- Show a standalone meaningful glyph, such as a status mark, named with `aria-label`.
- Draw a project-specific glyph from an SVG file with `src`.
- Render an A2UI `Icon` node on `<line-a2ui-surface>`, by name through the surface `iconMap` or by `svgPath` through `path` (ARCH §17.3, `docs/ARCHITECTURE.md:1585`; Phase 1 spec §6.G.4).

#### Anti-patterns

- A button whose only content is an icon. Use `<line-icon-button>`, which requires a name on an inner native `<button>` (Phase 1 spec §6.C.5, §10 SD36).
- A photo, avatar or raster image. Use `<img>` or `<line-avatar>`, because the injection step keeps vector shapes only (Phase 1 spec §10 SD95).
- An SVG with gradients, masks, clip paths, `<use>` or text. The allowlist drops those elements (Phase 1 spec §6.C.3 "Never passes"). Inline the `<svg>` in the consumer's own markup, where a slot accepts it (ARCH §11, `docs/ARCHITECTURE.md:493-505`).
- An icon that carries meaning nobody else states, left unnamed. A decorative icon is silent, so put the meaning in nearby text or name the icon with `aria-label`.
- A loading spinner. Use `<line-spinner>` (PRD §4.1).

#### User expectations

- The glyph sits in the text flow at the text size and in the text colour, with no extra spacing.
- A screen reader skips a decorative icon and announces a named icon as an image with its name.
- A directional icon marked `mirror` points the other way in a right-to-left page.
- A missing or broken icon leaves a blank space of the icon's size, and the page keeps working.
- Consumer CSS on `line-icon` and on `::part(svg)` overrides size, colour and placement.

## Part B — Technical Specification

### Anatomy

```
<line-icon>                  LineElement; the host carries the semantics and the box size
└── #shadow-root
    └── <svg part="svg" aria-hidden="true">   the glyph; absent in the C8 neutral state
```

- The shadow root holds at most one child, the root `<svg>` of the glyph. Lit renders it as a node value from `render()`, so Lit owns the shadow DOM (MANIFESTO Law 5).
- The shadow root has no slot, so light-DOM children are not rendered (Phase 1 spec §6.C.3 "has no default slot"; §10 SD14).
- A string from the registry or from `src` becomes a new `<svg>` built by the injection step (SVG injection below). The `path` property builds `<svg viewBox="0 0 24 24" fill="currentColor"><path d="…"></path></svg>` (Phase 1 spec §10 SD33; default F13). Both roots carry `part="svg"` (decision D4) and `aria-hidden="true"` (decision D5), so the host alone carries the semantics (decision D1).
- An `SVGElement` returned by a consumer resolver is inserted unchanged. It gets no `part` and no `aria-hidden` attribute (Phase 1 spec §6.C.3 "SVG injection"; decision D5; default F14).
- `:host([hidden]) { display: none }` is in the stylesheet, because `:host { display: inline-block }` beats the UA `[hidden]` rule, as Button, Stack and Separator found (`packages/line-components/src/button/button.ts:129-131`; `docs/specs/0011-separator.md:78`).

- Internally the element tracks one request counter and one rendered glyph (Source resolution below). Neither is public.

### Parts

| Part | Element | Purpose |
|------|---------|---------|
| `svg` | the root `<svg>` of the glyph | the drawn glyph; present only while a glyph from a string, `src` or `path` is shown |

- ARCH v0.8.16 §5 adds `::part(svg)` to the shared vocabulary for this part (`docs/ARCHITECTURE.md:303`; decision D4).
- MANIFESTO Law 1 holds. The host is the box and the consumer styles it with `line-icon { … }`; the glyph is the one inner zone, and `::part(svg)` reaches it.
- A consumer `SVGElement` has no `part` unless the consumer's resolver set one, because the element is inserted unchanged (decision D5; default F14). The host rules and the shadow rules for `svg` still size and mirror it (CSS custom properties below).

### Props

| Property | Attribute | Type | Default | Reflects | Description |
|----------|-----------|------|---------|----------|-------------|
| `name` | `name` | `string` | unset | yes | the icon name in the set that `library` names; resolves only with a non-empty `library` (decision D3) |
| `library` | `library` | `string` | unset | yes | the key the consumer registered a resolver under; no default set exists (decision D3; Phase 1 spec §6.C.3, §10 SD15) |
| `weight` | `weight` | `string` | unset | yes | passed to the registry as `options.weight` when non-empty, for example a Phosphor `fill`; the resolver validates it (Phase 1 spec §10 SD14; `packages/line-icons/src/resolvers/phosphor.ts:23-24`; default F17) |
| `mirror` | `mirror` | `boolean` | `false` | yes | flips the glyph horizontally when the host matches `:dir(rtl)`; CSS only, no script writes a style (Phase 1 spec §6.C.3; MANIFESTO Law 5) |
| `src` | `src` | `string` | unset | yes | URL of an SVG file, resolved against `document.baseURI` (default F2) |
| `path` | none | `string` | unset | no | SVG path data drawn in a `0 0 24 24` view box; JSON-serialisable, property only (Phase 1 spec §6.C.3, §10 SD33; default F13) |

- "Reflects" means a value the author or code sets is written to the attribute, and an unset value leaves none, as Stack AM-002 and Separator do (`docs/specs/0018-stack.md:122`; `docs/specs/0011-separator.md:114`). `mirror` must reflect, because the stylesheet keys on `:host([mirror])`; a `mirror` the surface sets as a property therefore still flips.
- `aria-label`, `aria-labelledby` and `aria-description` are plain host attributes. The component observes the first two through `observedAttributes` and declares no reactive property for them, so the native `ariaLabel` reflection of `HTMLElement` keeps working (A11y below; default F10). Button declares `ariaLabel` because it copies the value to an inner element (`packages/line-components/src/button/button.ts:107`); Icon copies nothing.

**Registry API** (Phase 1 spec §6.C.3 "Registry hook"; ARCH §11)

| Export | From | Shape |
|---|---|---|
| `LineIconRegistry` | `@websublime/line-components` (root `"."`) | `interface { resolve(library: string, name: string, options?: { weight?: string }): Promise<string \| SVGElement> }` |
| `setIconRegistry` | `@websublime/line-components` (root `"."`) | `(registry: LineIconRegistry \| undefined) => void`; `undefined` clears the registry (default F18) |
| `LineIcon.registry` | `@websublime/line-components/icon` | static getter and setter over the same slot |

- `src/shared/icon-registry.ts` keeps the slot `{ registry, events }` at `globalThis[Symbol.for('line.icon-registry')]` and creates it on first access, never at module load (Phase 1 spec §6.C.3; §12 AM-010).
- Both setters write `registry` and dispatch `line-icon-registry-change` on `events` (Phase 1 spec §6.C.3; §12 AM-010). `events` is the slot's `EventTarget`, not the host, so the event is no component event (Events below).
- The `line-icons` `IconRegistry` satisfies `LineIconRegistry`. A copy of `registry.ts:1-24` and the interface compiled with no error under TypeScript 7.0.2 `--strict` in a drafting probe on 2026-11-02, and a control with a wrong parameter type failed with TS2322 (`packages/line-icons/src/registry.ts:3-6`, `:19`). The C2 type-level case proves it in the repository (Tests).

**Source resolution**

| Order | Source | Used when | Result |
|---|---|---|---|
| 1 | `path` | `path` is a non-empty string | the built `<svg>`; synchronous |
| 2 | `src` | no `path`, `src` is a non-empty string | `fetch` of the file, then the injection step |
| 3 | registry | no `path` or `src`; `name` and `library` both non-empty | `registry.resolve(library, name, options)`, then the injection step for a string |
| — | none | none of the above | the C8 neutral state |

- The order is default F1. A higher source that fails does not fall back to a lower one; it leaves the C8 neutral state.
- `name` without `library`, or `library` without `name`, is no source (decision D3).
- The element resolves on its first update, when `path`, `src`, `name`, `library` or `weight` changes, on `line-icon-registry-change` while connected for a registry source, and on each later connect for a registry source (Phase 1 spec §6.C.3; default F19). `mirror` changes only CSS.
- Each resolution takes a new request number. A result applies only if its number is still the newest, so a stale response that settles after a newer request is dropped (default F3). The stale fetch is not aborted.
- The glyph on screen stays until the newest request settles, and is then replaced by the new glyph or cleared to the C8 state. A change that leaves no source clears the glyph at once (default F15).
- `src` fetches `new URL(src, document.baseURI)` with plain `fetch` in the default mode and credentials. An invalid URL, a network, CORS or CSP error, and a response that is not `ok` leave the C8 state. The response text passes the same injection step as a resolver string (default F2; Phase 1 spec §10 SD91).
- The registry call covers a missing registry, a registry without `resolve`, a synchronous throw, a rejection and a result that is neither a string nor an `SVGElement`. Each leaves the C8 state, and nothing reaches the consumer (Phase 1 spec §6.C.3 "Miss path", §10 SD92; MANIFESTO Law 9).
- The reference resolvers reject through `throw` inside `async` functions (`packages/line-icons/src/registry.ts:21`; `resolvers/icon-name.ts:5`; `resolvers/phosphor.ts:24`; `resolvers/fetch-icon.ts:13`, `:19`, `:26`, `:28`, `:32`), so the element catches a rejection, not a throw. The `LineIconRegistry` contract does not promise `async`, so the call also guards a synchronous throw.
- `<line-icon>` emits no event for any outcome (Phase 1 spec §6.C.3 "Miss path").

**SVG injection** (Phase 1 spec §6.C.3 "SVG injection", §10 SD91, SD95, SD97)

1. The string passes the Trusted Types policy `line-icon`, created lazily on the first string, when `trustedTypes` exists. A module-level guard creates it once per realm in each module copy and never at module load (Phase 1 spec §10 SD97). Its `createHTML` returns the string unchanged, because the allowlist step does the filtering. If `createPolicy` throws, this string and every later one in that module copy leave the C8 state.
2. `DOMParser.parseFromString(…, 'image/svg+xml')` parses it. A document that holds a `parsererror` element, or whose root is not an `svg` element in the SVG namespace, leaves the C8 state (default F16). Chromium and WebKit return an XHTML `html` root with the `parsererror` in its `body`, and Firefox returns a `parsererror` root in its own namespace, so the check looks the element up with `getElementsByTagName('parsererror')` (AM-001).
3. The step builds a new tree in the page document with `createElementNS` and `setAttribute`, copying only allowlisted elements in the SVG namespace and their allowlisted attributes. A dropped element is dropped with its subtree. Text, comment, CDATA and processing-instruction nodes are not copied, because no allowlisted element takes text. No parsed node enters the document (default F16).
4. An attribute passes when its namespace is null, its name is on the 36-name allowlist, it is not on the never-pass list, its value does not contain `url(`, matched ASCII case-insensitively, because CSS function names are case-insensitive (default F16), and its value contains no backslash. CSS decodes escapes such as `\75 rl(` or `u\rl(` after the literal match, so a backslash in any value drops the attribute; no Lucide or Phosphor value holds one (AM-002). The default `xmlns` of the root passes, and every `xmlns:*` declaration drops (Phase 1 spec §6.C.3).
5. The new root gets `part="svg"` (decision D4) and `aria-hidden="true"` (decision D5), and replaces the shown glyph. `aria-hidden="true"` overwrites any `aria-hidden` value the source carried.

- The allowlist and the never-pass list are the Phase 1 spec §6.C.3 tables, unchanged. Lucide and Phosphor files use only allowlisted names (R10 round 2 `docs/research/01-research-icon-round2.md:385-386`).
- Decision D5 adds one attribute after the allowlist step and changes neither list. The `role` and `aria-hidden` names stay allowlisted as Phase 1 spec §10 SD95 says, so no Phase 1 spec amendment follows. A source root with `role="img"` keeps the role, and `aria-hidden="true"` hides it.
- A Lucide file starts with a `<!-- @license … -->` comment before the root `<svg>` (`lucide-static` 1.56.0 `icons/house.svg`). The comment is a sibling of the root, so step 3 never copies it.
- An `SVGElement` result skips all five steps and is inserted as the same node, with no attribute added (Phase 1 spec §6.C.3; decision D5). A consumer who wants it hidden sets `aria-hidden="true"` on it in the resolver. A resolver that returns one shared node for several icons moves it from icon to icon, so the docs tell resolver authors to return a fresh node per call.
- Two module copies of `./icon` each create a `line-icon` policy. A page whose `trusted-types` directive lists `line-icon` without `'allow-duplicates'` lets only the first one through, and the second copy's icons stay in the C8 state. In chromium, firefox and webkit a second `createPolicy('line-icon')` throws without `'allow-duplicates'` and succeeds with it (AM-001). The docs name the policy and this case (Phase 1 spec §6.C.3 "The docs MUST name the policy").
- lit-html creates its own policy, `lit-html`, when it loads (`node_modules/.bun/lit-html@3.3.3/node_modules/lit-html/development/lit-html.js:69-70`). A page that enforces Trusted Types therefore lists both, `trusted-types line-icon lit-html`. Without `lit-html` the `createPolicy` call throws at module load and no Lit element defines, in all three engines (AM-001; Phase 1 spec §12 AM-064).

**Internals values** (decision D1)

| Host `aria-label` (trimmed) or `aria-labelledby` | `internals.role` | `internals.ariaHidden` |
|---|---|---|
| neither present and non-empty | `null` | `'true'` |
| either present and non-empty | `'img'` | `null` |

- The component writes these through `this[INTERNALS]` (`packages/line-core/src/line-element.ts:31-36`; `INTERNALS` at `packages/line-core/src/internals.ts:13`) on the first update and whenever either attribute changes, as Separator writes its role (`packages/line-components/src/separator/separator.ts:75-84`).
- An empty or whitespace-only `aria-label` and an empty `aria-labelledby` count as absent (default F10). The component does not check that the `aria-labelledby` ids resolve.
- The values do not depend on the glyph. A named icon in the C8 state still exposes an `img` with its name, so the meaning survives a failed load.
- The component never writes a `role` or `aria-*` attribute on the host. An author `role` or `aria-*` attribute therefore overrides the internals default (HTML §4.13.7.4, quoted in R8 `docs/research/01-research-accessibility.md:141-142`).

### CSS custom properties

| Property | Default | Used by part |
|----------|---------|--------------|
| `--line-icon-size` | `1em`, as the `var()` fallback | none; the host, as its inline and block size |

**Box and glyph**

| Element | Rules |
|---|---|
| `:host` | `display: inline-block`; `flex-shrink: 0`; `inline-size` and `block-size` both `var(--line-icon-size, 1em)`; no `color`, `vertical-align` or margin |
| `:host([hidden])` | `display: none` |
| root `svg` | `inline-size: 100%`; `block-size: 100%`; `display: block` and `max-width: 100%` come from `commonReset` (`packages/line-core/src/styles/reset.common.css:21-26`) |
| `:host([mirror]:dir(rtl))` root `svg` | `scale: -1 1` |

- `inline-block` keeps the icon in the text flow and lets it take a size, which an inline box ignores (default F4).
- `flex-shrink: 0` keeps the box in a crowded flex row, as Separator's host does. The root `svg` is sized in percentages, so it gives the host no min-content size, and without the rule Chromium shrank a `1em` icon to 5.7 px in a 40 px flex row (AM-001).
- The host reads `--line-icon-size` through a fallback and does not declare it on `:host`. A value set on the host or on any ancestor, such as a toolbar, therefore reaches it, and `1em` resolves against the icon's own font size (default F11). Button and Separator declare their tokens on `:host` instead (`packages/line-components/src/button/button.ts:115-127`; `packages/line-components/src/separator/separator.ts:35-37`), because their tokens style one element each.
- CSS `inline-size` and `block-size` on the root `svg` override the `width="24"` and `height="24"` presentation attributes of Lucide files, so the glyph fills the host whatever the file says. The `viewBox` keeps its aspect ratio.
- Colour comes from `currentColor`. Lucide files set `stroke="currentColor"` and Phosphor files `fill="currentColor"` (`lucide-static` 1.56.0 `icons/house.svg`; `@phosphor-icons/core` 2.1.1 `assets/regular/check.svg`), and the `path` glyph sets `fill="currentColor"` (default F13). The component sets no `color`, so the host inherits the text colour.
- The stylesheet sets no `fill` or `stroke`. A rule would beat the presentation attributes and turn Lucide's `fill="none"` outlines solid.
- `mirror` uses the individual `scale` property, not `transform`, so a consumer `transform` on `::part(svg)` still applies (default F21). Component CSS targets RTL with `:host(:dir(rtl))`, as `DirectionMixin` documents (`packages/line-core/src/mixins/direction.ts:58`).
- With no `vertical-align`, an inline-block with no line boxes sits with its bottom edge on the text baseline (CSS 2.1 §10.8.1). A consumer sets `vertical-align` on `line-icon` to centre it (default F12).
- In the C8 state the host keeps its size, so a late or failed glyph shifts no layout (default F7).
- In forced-colors mode `currentColor` follows the forced text colour, so the glyph stays visible with no extra rule. The Chromium Browser tier shows the Lucide stroke takes the forced text colour, not the page's `rgb(200, 0, 0)`, and differs from the `Canvas` background (AM-001).

#### Consumer styling

```css
/* Size: on one icon, or on a container for every icon inside it */
line-icon.large {
  --line-icon-size: 1.5rem;
}
.toolbar {
  --line-icon-size: 1.25em;
}

/* Colour: the glyph follows the host text colour */
line-icon.danger {
  color: var(--line-danger-text);
}

/* Placement in a line of text */
line-icon {
  vertical-align: -0.125em;
}

/* The glyph itself */
line-icon::part(svg) {
  stroke-width: 1.5;
}
```

- Normal outer declarations on `line-icon` beat the component's `:host` rules (ARCH §4), as the Stack and Separator Browser tiers proved (`packages/line-components/__tests__/integration/stack/stack.e2e.ts:153-173`).
- `stroke-width` on `::part(svg)` reaches the root only. Lucide sets `stroke-width` on the root and its shapes inherit it, so the rule above thins every stroke; the Browser tier reads `1.5px` on both `house` paths (AM-001).

### A11y

| Field | Value |
|-------|-------|
| Role | none and hidden by default, through `internals.ariaHidden = 'true'`; `img` on the host through `internals.role` when the host has a non-empty `aria-label` or `aria-labelledby` (decision D1; R8 `docs/research/01-research-accessibility.md:76`) |
| ARIA attributes | none written by the component; author `role` and `aria-*` attributes on the host override the internals defaults (decision D1) |
| Accessible name | the host `aria-label` or `aria-labelledby` names the `img` directly, because the role sits on the host (C5); nothing is copied |
| Focus | none; the host is not focusable and does not delegate focus |

- **Placement.** Phase 1 spec §10 SD31 puts interactive roles on inner native elements. Icon is not interactive, so D1 places the role on the host through internals, and the Phase 1 spec requires the accessibility-tree proof below for such roles (`docs/specs/01-spec-core-primitives.md:1177`; §10 SD39; §12 AM-058).
- **Agent path.** A `basic` `Icon` node gives `name`, as an enum, `{ svgPath }` or a binding (R10 `docs/research/01-research-icon.md:59-67`), and a `line` `Icon` node gives `name` or `path`. Either node may carry `accessibility` from the `ComponentCommon` mixin, and the surface sets no label from it (Phase 1 spec §6.G.4 Accessibility, AM-067). A surface icon is therefore always decorative (decision D1).
- **Children.** The injected root `<svg>` carries `aria-hidden="true"` (decision D5), so no glyph built from a string or from `path` exposes a node, whatever the host semantics are. In the decorative case the internals `aria-hidden` also hides the whole subtree. A consumer `SVGElement` inside a named host is a different case. Chromium exposes it as its own `image` node, with or without a `role` of its own, unless the node carries `aria-hidden="true"`, so ARIA's presentational `img` children do not hide it (AM-001). The docs tell resolver authors to set `aria-hidden="true"` on a node that should stay silent.
- **Engine support.** `ElementInternals.role` ships in Chrome 103, and the string `aria*` properties, `ariaHidden` among them, in Chrome 81; both ship in Firefox 119 and Safari 16.4 (R8 `docs/research/01-research-accessibility.md:106-107`). The Chromium check below shows that Chromium ignores a host whose internals hold `ariaHidden = 'true'` (AM-001).

**What axe proves here** (Phase 1 spec §7.4; R8 §2.4)

- axe-core 4.14.0 cannot see `internals.role` or `internals.ariaHidden`, because `LineElement` keeps the internals behind a Symbol-keyed prototype accessor that axe's lookup misses (Phase 1 spec §10 SD19; the analysis in `docs/specs/0011-separator.md:221`). axe sees a role-less custom element with an `aria-hidden` `<svg>` in its shadow root.
- A labelled host passes `aria-prohibited-attr` in 4.14.0, for the reason Separator recorded (`docs/specs/0011-separator.md:222`).
- Zero violations in every Icon story, in chromium, firefox and webkit (A11y tier, AM-001). They prove nothing about the hidden or `img` semantics of the host, because axe sees neither (Phase 1 spec §7.4).
- An injected `<svg>` whose source root carries `role="img"` would match axe `svg-img-alt`, because the allowlist keeps `role` and drops `aria-label` and `<title>` (`node_modules/.bun/axe-core@4.14.0/node_modules/axe-core/axe.js:37930-37943`; Phase 1 spec §6.C.3 allowlist). Its `aria-hidden="true"` takes it out of the rules that skip hidden content, so axe reports no `svg-img-alt` for it (decision D5). The A11y tier proves both halves on the Foreign role story: zero violations as rendered, and `svg-img-alt` once the test removes the injected `aria-hidden` (AM-001). Neither Lucide nor Phosphor files carry `role` (R10 round 2 `:385-386`).
- The Storybook panel's axe-core 4.11.4 shows a false `aria-prohibited-attr` on a labelled host, as it does for Separator (`docs/specs/0011-separator.md:224`). The panel gates nothing (Phase 1 spec §7.4 "Author panel").

**Accessibility tree** (Phase 1 spec §6.C.4 notes, §7.4, §10 SD39, §12 AM-058)

- **Chromium accessibility tree, automated.** A Browser-tier test opens a CDP session with `page.context().newCDPSession(page)` and reads `Accessibility.getPartialAXTree` for each host, as the Separator test does (`packages/line-components/__tests__/integration/separator/separator.e2e.ts:272-299`). It asserts the following.
  - A host with no label, with a resolved glyph, is ignored, and no node of its subtree is exposed.
  - A host with `aria-label="Settings"` has the image role and the name "Settings". Chromium reports ARIA `img` with the CDP role value `image` (AM-001).
  - A host with `aria-labelledby` pointing at a light-DOM element takes that element's text as its name.
  - Removing `aria-label` returns the host to ignored, and adding it again restores the image role and name.
  - A host with `aria-label=" "` is ignored (default F10).
  - A named host exposes no child node for its `<svg>`.
  - A named host in the C8 state, with an unknown name, still has the image role and its name.
  - An author `aria-hidden="true"` on a named host makes it ignored, and an author `role="graphics-symbol"` with `aria-label` replaces the image role, so author attributes override the internals defaults.
  - A consumer `SVGElement` inside a named host is exposed as a child `image` node unless it carries `aria-hidden="true"`; inside a decorative host it is ignored (AM-001).
- **Result, Chromium accessibility tree** (C2 Browser tier, `packages/line-components/__tests__/integration/icon/icon.e2e.ts`, 2026-11-02): every assertion above holds in Chromium. An unlabelled host is ignored and exposes no descendant; `aria-label="Settings"` gives role `image` and name "Settings" with no child node for the injected `<svg>`; `aria-labelledby` gives the referenced text "Account settings"; `aria-label=" "` is ignored; a named host with an unknown name keeps role `image` and its name; removing `aria-label` makes the host ignored and adding it back restores `image` and the name; an author `aria-hidden="true"` makes a named host ignored and an author `role="graphics-symbol"` gives `graphics-symbol`. A consumer `<svg>` without `aria-hidden` inside a named host shows as a child `image`. The internals read-back holds the internals table in chromium, firefox and webkit (AM-001).
- **Firefox and WebKit.** CDP sessions are Chromium-only (`docs/specs/0011-separator.md:235`). The Browser tier reads `role` and `ariaHidden` back through the `INTERNALS` symbol in chromium, firefox and webkit, through a fixture module that re-exports `INTERNALS`, as the Separator test does (`separator.e2e.ts:245-247`). It covers every row of the internals table, the blank label, a label added and removed, and `aria-labelledby`. It proves the values each engine holds, not what the engine exposes.
- A manual screen-reader pass is optional and never blocks the row (Phase 1 spec §12 AM-058).
- Firefox and WebKit exposure to assistive technology stays unverified by any check above; the gap is recorded here (Phase 1 spec §6.C.4 notes; §12 AM-058; Open Question 3).

| D1 | How does Icon expose decorative and meaningful semantics? (Phase 1 spec §6.C.4 C2 row, "Decorative vs labelled semantics") | Decorative by default. | D5 | How does an injected SVG stay out of the accessibility tree? | After sanitising a parsed SVG string, `<line-icon>` sets `aria-hidden="true"` on the injected root `svg`, so axe skips the subtree and the host alone carries the semantics (D1).
