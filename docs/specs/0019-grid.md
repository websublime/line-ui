### P1 — Accessibility tree, axe and Tab

Each case sat in its own `<div id="case">`. "Children" are three `<div>`s with the text One, Two and Three.

| Case | Chromium tree under the wrapper (CDP) | `ariaSnapshot()`, three engines | axe 4.14.0, §7.4 tags and all rules |
|---|---|---|---|
| A. `columns="3" min-column-width="none"`, children | no node for the host; three `generic` nodes with their text | `- text: One Two Three` | none |
| B. empty grid | nothing | empty | none |
| C. A with `aria-label="Products"` | `generic "Products"` holding the three `generic` children | `- text: One Two Three` | none |
| D. empty grid with `aria-label="Products"` | `generic "Products"` | empty | none |
| E. `role="list" aria-label="Products"`, children with `role="listitem"` | `list "Products"` with three `listitem` | `- list "Products":` with three `listitem` | none |
| F. `role="list"`, plain `<div>` children | `list` with three `generic` | `- list: One Two Three` | `aria-required-children` |
| G. `role="grid"`, plain `<div>` children | `grid` with three `generic` | `- grid: One Two Three` | `aria-required-children` |

- A role-less grid adds no node of its own; its children read in DOM order (A).
- A host `aria-label` names a `generic` in the Chromium tree (C, D). ARIA 1.2 prohibits that name (R8 `docs/research/01-research-accessibility.md:55`), and axe does not report it, through the custom-element exemption of `aria-prohibited-attr` that `0018-stack.md:169` traces.
- Author list semantics work on the host with no node in between (E), and axe catches a list without items (F).
- `role="grid"` on a layout grid is the misuse R8 warns about (`:81`), and axe reports it (G).
- Tab from a button before the grid lands on the button after it, so the host takes no focus.

- The slotted children become the host's grid items through the bare slot, in three engines.

- A consumer `column-gap` desynchronises the count formula, and a consumer `--line-grid-column-gap` does not (F3).
- A unitless `0` in a token that enters the formula collapses the grid to one column, so the component writes `0px` and the docs say so (D8).
- The template follows the writing direction, and consumer CSS on the host beats every `:host` default.
- `:host { display: grid }` beats the UA `[hidden]` rule, so the `:host([hidden])` rule is needed (D3).

|---|---|

- A host cannot answer a container query about its own size, so a container-query Grid needs an inner wrapper, a `generic` node between a host `role="list"` and its items (F1 (d); `0018-stack.md` Open Question 1).

- A shadow `:host` rule does answer a query about a page ancestor container, in three engines, so a consumer can make a grid respond to its container with ordinary CSS (Consumer styling).
- Viewport media queries work from the shadow sheet, but only with literal lengths, because `packages/line-tokens/src/breakpoints.css:6-9` notes that custom properties cannot be used in `@media` (F1 (c)).

### What the probes settle

- The host can be the grid container over a bare slot, as Stack's flex host is, and list roles reach the items (P1, P2; D2).
- One template rule over three tokens gives a fixed count, an intrinsic count, or "at most N columns, each at least W", in three engines, with no breakpoint and no wrapper (P2; F1).

- What a screen reader announces for a role-less grid of cards, and whether it reads them in DOM order. P1 reads the Chromium tree only.
- Firefox and WebKit accessibility trees. Playwright's snapshot is its own computation from the DOM (Phase 1 spec §12 AM-058).
- Whether users find an intrinsic grid that drops columns as it narrows more predictable than one that changes at fixed breakpoints, which F1 weighs.

## Part A — Requirements

### Overview

#### Description

`<line-grid>` lays out its children in rows of equal columns (PRD §4.1, `docs/PRD.md:264`). The host itself is the grid container, and the children are its grid items. The column count adapts to the width the grid has. `columns` caps how many columns a row holds, and `min-column-width` sets how narrow a column may get before the grid moves to fewer columns (F1 (b)). The gap comes from the `--line-layout-gap-*` scale, as on Stack. Grid adds no role, no state and no behaviour, so it stays a `generic` element in the accessibility tree (R8 `docs/research/01-research-accessibility.md:81`).

#### Use cases

- A gallery of cards that shows as many columns as fit, one on a phone and four on a wide screen.
- A dashboard of tiles with at most three columns, each at least 12rem wide.
- A fixed form layout of two equal columns at any width (`min-column-width="none"`).
- A list of products, with `role="list"` on the host and `role="listitem"` on the children.
- An agent-built tile layout on `<line-a2ui-surface>` through the `line` catalog.

#### Anti-patterns

- An interactive data grid with arrow-key navigation between cells. ARIA `grid` and APG Grid describe that widget, and Grid is not it (R8 `:81`); use the Data Grid of PRD §4.9, a Phase 7 component (PRD `:388`, `:1104`). Never put `role="grid"` on `line-grid` (P1 G).
- One row or one column of items. Use `<line-stack>` (row 01-C3).
- Centring one child in a box. Use `<line-center>` (row 01-C18).
- A two-dimensional page layout with named areas, a sidebar and a header. Write CSS Grid with `grid-template-areas` on the page's own element; Grid has no areas (F9).
- A tabular data set. Use a `<table>`.

#### User expectations

- Children appear in source order, row by row, in the writing direction of the page.
- Columns are equal in width, and the grid moves to fewer columns as it narrows, never to columns too narrow to read (F1 (b)).
- Spacing between items is even and follows the design tokens.
- Grid adds nothing to what a screen reader announces, and focus moves through the children in source order.
- Consumer CSS on `line-grid` overrides any layout default.

### Connections

| Component | Relation | Connects through |
|-----------|----------|------------------|
| any element or `line-*` component | child | the default slot; Grid never imports a child (MANIFESTO Law 4; Phase 1 spec §6.C.6, `:1228`) |
| `<line-stack>` | child or parent | the default slot; a stack inside a cell, or grids inside a stack |
| `<line-a2ui-surface>` | orchestrator | creates `line-grid` by tag for a `line` catalog `Grid` node and puts `children` in the default slot (ARCH §17.4; Phase 1 spec §6.G.4); no A2UI `basic` type maps to it (P9; D12) |

- In a flex row, such as a horizontal `<line-stack>`, or in an `auto` grid track, `line-grid` sizes to its content, so its columns have no room. Give it `flex: 1` or a width there (P3).

### Variants

| Attribute | Values | Use when |
|-----------|--------|----------|
| `columns` | `1` … `12` | `1` for one column; `2`–`12` for the most columns in a row; no attribute gives at most `12` |
| `min-column-width` | `none \| xxs \| xs \| sm \| md` | `xxs` (12rem), `xs` (16rem), `sm` (24rem) or `md` (32rem) for the narrowest column before the grid drops one; `none` to keep all `columns` at any width; no attribute gives `xs` |
| `gap` | `0 \| 1 \| 2 \| 3 \| 4 \| 5` | `0` for no space; `1`–`5` for growing space on the `--line-layout-gap-*` scale (0.25rem, 0.5rem, 1rem, 1.5rem, 2rem); no attribute gives step `2` |

- `columns`, `min-column-width` and `gap` are the C6 semantic variants. Each value only redeclares the default of one `--line-grid-*` token on `:host` and adds no other rule (ARCH §17.2 C6; F1 (b), F3 (b)).
- `align` and `justify-items` are layout props, not C6 variants, as Stack's `justify` and `align` are. Each maps to a CSS alignment property on `:host` (Props below; F4 (a)).
- An unknown value of a variant behaves as no attribute, and the attribute keeps what the author wrote (C8; D9).

## Part B — Technical Specification

### Anatomy

```
<line-grid>                  LineElement; display: grid on :host; the host is the grid container
└── #shadow-root
    └── <slot>               slotted children are the host's grid items
```

- The shadow root holds only a bare `<slot>`, with no wrapper element, as on Stack (`0018-stack.md` Open Question 1; D2).
- A `<slot>` has `display: contents` by default, so slotted children take part in the host's grid directly (P2, in three engines).
- No `generic` node sits between a host `role="list"` and its `role="listitem"` children (P1 E).
- `commonReset` sets nothing on `:host` (`packages/line-core/src/styles/reset.common.css:2-38`), so `:host { display: grid }` does not conflict with it.
- `:host { display: grid }` beats the UA `[hidden]` rule, so the stylesheet adds `:host([hidden]) { display: none }` (P2; D3).

### Props

| Property | Attribute | Type | Default | Reflects | Description |
|----------|-----------|------|---------|----------|-------------|
| `columns` | `columns` | `'1' \| '2' \| … \| '12'` | `undefined` (at most 12) | yes | the most columns in a row; C6 variant over `--line-grid-columns` (F1 (b), F7 (a)) |
| `minColumnWidth` | `min-column-width` | `'none' \| 'xxs' \| 'xs' \| 'sm' \| 'md'` | `undefined` (`xs`) | yes | the narrowest column before the grid drops one; C6 variant over `--line-grid-min-column-width`; `none` keeps all `columns` at any width (F1 (b)) |
| `gap` | `gap` | `'0' \| '1' \| '2' \| '3' \| '4' \| '5'` | `undefined` (step `2`) | yes | space between rows and columns; C6 variant over `--line-grid-gap` (F3 (b)) |
| `align` | `align` | `'start' \| 'center' \| 'end' \| 'stretch'` | `'stretch'` | yes | each child's place within its row; maps to `align-items` (F4 (a)), never to `text-align` (AM-003) |
| `justifyItems` | `justify-items` | `'start' \| 'center' \| 'end' \| 'stretch'` | `'stretch'` | yes | each child's place within its column; maps to `justify-items` (F4 (a)) |

- "Reflects" means a value the author or code sets is written to the attribute; a default leaves no attribute (Lit `useDefault: true` for `align` and `justifyItems`; `undefined` for the variants), so an unknown author value stays as written (C8) and removing the attribute restores the default, as on Stack (`0018-stack.md` AM-002; D9).
- Each variant is a converter that returns `undefined` for an unknown value, as Stack's `gapConverter` does (`packages/line-components/src/stack/stack.ts:25-27`); `align` and `justifyItems` use Stack's `enumConverter` with the fallback `stretch` (`:20-22`).
- One template rule on `:host` reads the three tokens (CSS custom properties). `columns="2"` with `min-column-width="none"` is two equal columns at any width; `columns="4"` alone is at most four columns of at least 16rem; no attribute is as many 16rem columns as fit, up to 12 (P2).
- `columns="1"` is one column at any width, and `min-column-width="none"` without `columns` is twelve equal columns (P2).
- The `justify-items` name keeps `justify` free of a second meaning, because Stack's `justify` distributes items (`justify-content`) and that has no effect on `1fr` tracks (P5; F4).
- Grid has no `rows`, `flow`, `areas` or `inline` prop (F9).

- Set `--line-grid-column-gap`, not `column-gap`, to change the column gap, because the count formula reads the token (P2).
- Write `0px`, not `0`, when setting a gap or minimum token to zero (P2; D8).
- `grid-column: span N` on a child works, but in an intrinsic grid it adds an implicit column once fewer than `N` columns fit; pair it with `min-column-width="none"` or a container query (P4; F5).

### A11y

| Field | Value |
|-------|-------|
| Role | none; the host stays `generic` and adds no node to the Chromium tree when it has no name (R8 `:81`; P1 A; Phase 1 spec §6.C.4 C17 row) |
| ARIA attributes | none set by the component; it never writes `role`, `aria-*` or `internals.role`, and it leaves an author-set host `role` alone (D5) |
| Accessible name | none by default; see the C5 note below |
| Focus | none; the host is not focusable and does not delegate focus (P1; D6) |

- **C5.** ARIA 1.2 prohibits `aria-label` and `aria-labelledby` on `generic`, so a name on a role-less `line-grid` names nothing a user can reach (R8 `:55`). Chromium still exposes it as a named `generic`, and axe 4.14.0 does not report it (P1 C, D; `0018-stack.md:168-169`). A name applies only with an author role that allows one, such as `role="list"` or `role="group"`.
- **Lists.** A list of cards puts `role="list"` on the host and `role="listitem"` on each child, and a story documents it (P1 E). axe reports a `role="list"` host whose children lack `listitem` (P1 F).
- **Not a widget.** `role="grid"` on `line-grid` claims an interactive widget with arrow-key navigation, which Grid does not provide; axe reports it (P1 G; R8 `:81`). The docs say so.
- **Order.** Grid places items in source order, row by row, and offers no prop that reorders them (F9). Consumer CSS that moves items with `order`, `grid-row` or `grid-auto-flow: dense` can make the visual order differ from the reading and focus order (P4; WCAG 1.3.2, 2.4.3), and the docs warn against it.
- **Proof (D20).** No role, name or ARIA value lives in internals, so the CDP-and-read-back rule for internals roles does not apply (Phase 1 spec `:1180`). The Browser tier checks the tree with `ariaSnapshot()` in three engines and a Chromium CDP assertion.
- **Firefox and WebKit.** No check reads their accessibility trees, and no screen reader was run. The gap is recorded here (Phase 1 spec `:1180`; §12 AM-058).

### F1 — Responsive column model

**Decision.** Miguel chose option (b) on 2026-11-16, so `columns` caps the count, `min-column-width` sets the narrowest column, and one template rule needs no breakpoint.

**Evidence.** PRD §4.1 asks for "responsive column control" (`docs/PRD.md:264`). In probe P2 one `:host` template over a count token and a minimum token gives an intrinsic grid (1, 2, 3, 5 columns at 300, 600, 1000, 1400 px with no attributes), a capped one (`columns="4"`: 1, 2, 3, 4), and a fixed one (`min-column-width="none"`: 4 at every width), identical in three engines, with RTL for free. In probe P3 a host cannot answer a container query about its own size; an inner wrapper can, but it collapses to zero width in flex and `auto` grid tracks, and it puts a `generic` between a host list and its items, which Stack rejected (`0018-stack.md` Open Question 1). A shadow `:host` rule does answer a page ancestor's container query, so consumers can add their own breakpoints to any option. Media queries need literal lengths (`packages/line-tokens/src/breakpoints.css:6-9`) and follow the viewport, not the grid's width, so a grid in a sidebar or on an agent surface of unknown width gets the viewport's columns. Web Awesome's `wa-grid` is intrinsic with a 20ch minimum and no count (P10); Radix Themes `Grid` takes a count per viewport breakpoint (P10). The agent path carries any string enum (P8, rule C1).

| Option | What it decides | No attributes (C8) | RTL | Agent path (C1) | Consequence |
|---|---|---|---|---|---|
| (a) Fixed count | `columns` `1`–`12` sets `repeat(N, minmax(0, 1fr))`; no responsive behaviour in the component | one column [INFERENCE: the draft would have picked 1] | follows the writing direction | one enum | Smallest API, Radix's base case. Every responsive grid needs consumer media or container queries on the host, and an agent cannot ask for one. The PRD's "responsive" lives only in docs (Spec drift found, item 7) |
| (b) **Recommended.** Intrinsic count with a cap | `columns` `1`–`12` is the most columns, default 12; `min-column-width` `none \| xxs \| xs \| sm \| md` is the narrowest column, default `xs` (16rem); one template rule, no breakpoint | as many 16rem columns as fit, up to 12 (P2) | follows the writing direction (P2) | two enums | Responds to the grid's own width in any container, with no wrapper (P2, P3). `columns` alone still drops columns on narrow screens, so a rigid count needs `min-column-width="none"`. Consumers add breakpoints by setting the tokens in their own queries (P3) |
| (c) Viewport breakpoints | `columns`, `columns-sm`, `columns-md`, `columns-lg`, `columns-xl` set the count at `--line-breakpoint-*` widths, written as literal `@media` lengths | `columns` default (one) [INFERENCE] | follows the writing direction | five enums | Familiar from Radix (P10). Follows the viewport, not the grid, so a sidebar grid gets desktop columns; the literal lengths duplicate the breakpoint tokens and drift if they change (`breakpoints.css:6-9`) |
| (d) Container-query breakpoints | the same per-breakpoint attributes against the grid's own width, through `container-type` on the host and an inner `part="root"` grid | as (c) | follows the writing direction | five enums | Responds to the grid's width, but needs a wrapper node that breaks host list roles and a part; the host collapses to zero width in flex rows and `auto` tracks (P3) |

### F2 — Short rows

**Decision.** Miguel chose option (a) on 2026-11-16, so the template uses `auto-fill` and an item keeps its column width in a short row.

**Evidence.** In probe P2, with two items at 1000 px, `auto-fill` keeps the empty track, so each item is 328 px with no attributes and 244 px, a quarter, with `columns="4" min-column-width="none"`; `auto-fit` collapses the empty tracks, so both items stretch to 496 px. `line-tokens` ships both templates (`layouts.css:16-17`); Web Awesome's `wa-grid` uses `auto-fit` (P10); a Radix count is `repeat(N, minmax(0, 1fr))`, which behaves as `auto-fill` here.

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** `auto-fill` | an item keeps its column width when its row is short | A four-column grid with two items still looks like four columns, as a fixed count does; the last row lines up with the rows above |
| (b) `auto-fit` | items in a short row stretch to fill it | One item fills the whole width; a "four-column" grid with two items shows two wide columns. Matches Web Awesome |
| (c) A boolean `stretch` attribute | `auto-fill` by default, `auto-fit` when set | Both behaviours; one more prop for authors and agents, and one more C6 variant over a `--line-grid-track` token (P2 probe switch) |

### F3 — Gap

**Decision.** Miguel chose option (b) on 2026-11-16, so one `gap` attribute sets `--line-grid-gap`, and `--line-grid-row-gap` and `--line-grid-column-gap` default to it.

**Evidence.** Stack takes `gap` `0`–`5` over `--line-stack-gap` (`0018-stack.md:60-62`, `:143`). The count formula of F1 (b) subtracts the column gap, and in probe P2 a consumer `column-gap: 40px` drops a four-column grid to three columns, while `--line-grid-column-gap: 40px` keeps four. Radix Themes `Grid` has `gap`, `gapX` and `gapY` (P10). A2UI has no gap prop on any layout type (`0018-stack.md:218`).

| Option | What it decides | Consequence |
|---|---|---|
| (a) Stack's pattern exactly | `gap` `0`–`5` over one `--line-grid-gap` that sets both gaps | Same shape as Stack. A consumer who sets `column-gap` breaks the count under F1 (b) (P2), and `row-gap` alone is the only safe split |
| (b) **Recommended.** One attribute, three tokens | `gap` `0`–`5` over `--line-grid-gap`; `--line-grid-row-gap` and `--line-grid-column-gap` default to it and drive `row-gap`, `column-gap` and the formula | Same attribute as Stack. Consumers split rows and columns through tokens that keep the count right (P2). Agents get one gap |
| (c) Three attributes | `gap`, `row-gap` and `column-gap`, each `0`–`5`, over the three tokens of (b) | Agents and authors split gaps without CSS. Two more enums, and the `column-gap` attribute must win over `gap` in the stylesheet |
| (d) Stack's scale with a wider default | as (b), with step `3` (1rem) as the default | Card grids often want more space than a stack [INFERENCE]. Two layout helpers with different defaults |

### F4 — Alignment

**Decision.** Miguel chose option (a) on 2026-11-16, so Grid takes `align` and `justify-items`.

**Evidence.** In probe P5, `align-items` and `justify-items` move each child within its cell, and `justify-content` has no effect while the tracks end in `1fr`, which every F1 option uses. Stack's `align` is `align-items` and its `justify` is `justify-content`, with `spaceBetween` and the other distribution values (`0018-stack.md:117-118`). Radix Themes `Grid` uses `align` for `align-items`, `justify` for `justify-content` and `justifyItems` for `justify-items` (P10).

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** `align` and `justify-items` | `align` → `align-items` and `justifyItems` (attribute `justify-items`) → `justify-items`, each `start \| center \| end \| stretch`, default `stretch` | `align` means what it means on Stack; `justify` never means two things across line's layout helpers, and the name matches Radix |
| (b) `align` and `justify` | the same two properties, with `justify` mapping to `justify-items` | Shorter. Stack's `justify` distributes items and takes other values, so an agent that learned Stack sends `spaceBetween` and gets nothing |
| (c) `align` only | `align-items` | Covers vertical alignment of uneven cards. Horizontal placement within a cell needs consumer CSS |
| (d) None | stretch in both axes | Smallest API. Agents cannot centre an icon in a tile |
| (e) Item and content alignment | (a) plus `alignContent` and `justifyContent` with Stack's distribution values | Content alignment does nothing with `1fr` tracks (P5), so the props would only matter after a consumer rewrites the template |

### F5 — Child spanning

**Decision.** Miguel chose option (a) on 2026-11-16, so Grid offers nothing for spanning, and the docs show consumer `grid-column` rules with `1 / -1` and the span caveat.

**Evidence.** MANIFESTO Law 4 forbids a component that imports another to compose its children (`docs/MANIFESTO.md:45`). In probe P4 a consumer rule on a light-DOM child spans two columns with no Grid code, and both shadow hooks, `::slotted([data-span="2"])` and `::slotted(*) { grid-column: span var(--line-grid-span, 1) }`, do the same. A `span 2` in an intrinsic grid that fits one column adds an implicit column and squeezes the next item to 8 px; `grid-column: 1 / -1` is safe at every width, and Web Awesome ships it as `.wa-span-grid` (P10). A2UI's only per-child layout hint is `weight` for `Row` and `Column` children (P9), so no agent route to a span exists. SD12 rejected "a Grid family" (`docs/specs/01-spec-core-primitives.md:2359`).

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** Nothing | the consumer writes `grid-column` on the child; the docs show `1 / -1` and the span caveat | No new contract; works today (P4). Agents cannot span |
| (b) `::slotted` rules on a child attribute | `data-span="2"` … `"12"` and `"full"` on any child set its `grid-column` from the shadow sheet | Markup-only spanning (P4). A `data-*` contract Grid reads from elements it does not own; the span caveat stays; agents still need a surface rule to write the attribute |
| (c) A child token | `::slotted(*) { grid-column: span var(--line-grid-span, 1) }`, and the consumer sets `--line-grid-span` on the child | Token-only spanning (P4). A token that lives on children, a new pattern for line; the caveat stays |
| (d) A `line-grid-item` element | `./grid` registers a second tag with a `span` prop | Agents could span through the catalog. A family entrypoint that SD12 rejected, so it would have needed a Phase 1 spec AM (Spec drift found, item 5) and a second descriptor |

### F6 — Agent props and the basic catalog

**Decision.** Miguel chose option (a) on 2026-11-16, so the descriptor exposes all five layout props and `children`, in the `line` catalog only.

**Evidence.** In probe P8 the five layout props and `children` reach the `line` catalog, the inline projection validates, and all three providers' tools carry the five props without `children` or accessibility parameters. The surface renders a Grid node with its children and removes the attributes of unset props. | Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** Every layout prop | `columns`, `minColumnWidth`, `gap`, `align`, `justifyItems`, `children`; `line` catalog only | Agents get what authors get, as on Stack (P8). Five enums in each tool |
| (b) Structure only | `columns`, `gap`, `children` | A smaller tool; agents cannot ask for a fixed count or alignment, and every agent grid drops columns at 16rem |
| (c) Structure and responsiveness | `columns`, `minColumnWidth`, `gap`, `children` | Agents control the column model; alignment stays with the host app |

### F7 — Type of `columns`

**Decision.** Miguel chose option (a) on 2026-11-16, so `columns` is a string enum `'1'`–`'12'`.

**Evidence.** Phase 1 spec §6.G.1 types a number prop as `DynamicNumber` and an enum as `z.enum` with plain `.describe()` (`:1326`). In probe P8, a `DynamicNumber` `columns` binds to the data model and updates the same element, but the surface writes `2.5` as `columns="2.5"`, which no attribute selector matches; a string enum rejects a number `3` with `VALIDATION_ERROR` and renders nothing. Stack's `gap` is a string enum of digits (`0018-stack.md:119`); Skeleton's `lines` is a number clamped in `willUpdate` because it counts rendered items (`0016-skeleton.md` D8). MANIFESTO Law 5 keeps styles out of TypeScript, so a number reaches CSS only through attribute selectors.

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** String enum | `columns: '1' \| … \| '12'`; `z.enum` in the descriptor | The attribute text and the CSS selector always agree; the same shape as `gap`. An agent that sends a number gets a validation error, and `columns` cannot bind to the data model |
| (b) Number | `columns: number` (`type: Number`); `DynamicNumber` in the descriptor | Natural for agents and bindable (P8). A non-integer or out-of-range value keeps its attribute text, so the property and the styling disagree unless `willUpdate` normalises the attribute, which Lit allows but no other line component does |

### F8 — Host naming on the agent path

**Decision.** Miguel chose option (a) on 2026-11-16, so the descriptor takes `hostNaming: never`, and Phase 1 spec AM-101 adds Grid to the four lists of components that take no host name.

| (a) **Recommended.** `never` | the surface sets no `aria-label` or `aria-description` on a Grid node; the tool carries no `accessibilityLabel` or `accessibilityDescription` | Mirrors Kbd and Skeleton. ### F9 — Other grid props
