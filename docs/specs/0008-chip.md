### P1 — `@zag-js/toggle` through `LineMachineController` (happy-dom)

The probe host extended `LineElement` and built a `LineMachineController` with the toggle `machine` and the live props function `() => ({ pressed: this.pressed, disabled: this.disabled, onPressedChange })`. `pressed` and `disabled` were reflected Lit booleans with constructor default `false`. `onPressedChange(next)` set `this.pressed = next` and dispatched a bubbling `line-change` with `{ value: next }`. The render read `toggle.connect(service, identityNormaliser)`.

| Check | Result |
|---|---|
| Start | one state, `idle`; context `pressed` is `false`, read from the prop; one host update |
| `connect().getRootProps()` | `type: "button"`, `data-scope: "toggle"`, `data-part: "root"`, `disabled: false`, `aria-pressed: false` (a boolean), `data-state: "off"`, `onClick`; `data-pressed` and `data-disabled` are absent while false |
| `connect().getIndicatorProps()` | `data-scope: "toggle"`, `data-part: "indicator"`, `data-state: "off"` |
| `send({ type: 'PRESS.TOGGLE' })` | `pressed` is unchanged synchronously and `true` after one microtask; `onPressedChange(true)` once; one `line-change`; one host update; context reads `true`; host attribute `pressed=""`; inner `aria-pressed="true"` |
| `pressed` set from outside, `true` → `false` | no `onPressedChange` and no `line-change`; context follows the property; one host update |
| `PRESS.TOGGLE` while `disabled` | the machine flips `pressed` and calls `onPressedChange`; it has no `disabled` guard |
| `getRootProps().onClick` while `disabled` | no flip |
| `getRootProps().onClick` with a click whose default was prevented | no flip |
| `onPressedChange` that leaves `pressed` unchanged | context stays `false`, because the bindable is controlled |
| `PRESS.SET` to the current value; to the other value | no `onPressedChange`; one `onPressedChange` |
| A machine whose `initialState` throws | `fallback` is `true`, one `console.error`, and the host still renders its inner `<button>` |
| Nine `PRESS.TOGGLE` sends in one task | nine `onPressedChange` calls, nine `line-change` events, one host update, final `pressed` `true` |

- `VanillaMachine.send` queues each event with `queueMicrotask` (`node_modules/@zag-js/vanilla/dist/machine.mjs:75-79`), so a flip lands one microtask after the send.
- The bindable is controlled while the props function returns a defined `pressed` (`node_modules/@zag-js/vanilla/dist/bindable.mjs:13-30`). `context.set` then stores nothing and only calls `onChange`, so the component's property set is the one source of the host update.
- `PRESS.TOGGLE` and `PRESS.SET` carry no guard (`@zag-js/toggle` 1.47.0 `dist/toggle.machine.mjs:24-31`). Only `connect().getRootProps().onClick` reads `disabled` and `defaultPrevented` (`dist/toggle.connect.mjs:22-26`).

### P2 — disabled forms and the name of a slot fallback (three engines)

Each case mounted a plain custom element whose shadow root held `<button type="button" aria-pressed="false">` around a default slot, with `delegatesFocus: true`. The `native` host's button carried `disabled`, the `aria` host's button carried `aria-disabled="true"`, and the `enabled` host's button carried neither. Two more hosts held `<button aria-pressed="true"><slot>Fallback label</slot></button>`, one empty and one with a slotted `<span>Slotted</span>`. Tab ran from a native button before the hosts; webkit on macOS used `Alt+Tab`, as `packages/line-components/__tests__/integration/alert/alert.e2e.ts:96-98` does.

| Check | chromium | firefox | webkit |
|---|---|---|---|
| Tab order | `before` → `aria` → `enabled` → `after`; the `native` host is skipped | same | same |
| Host `click` listener calls after `page.click` on each host (forced) | `native` 0, `aria` 1, `enabled` 1 | same | same |
| Chromium AX node of each inner button | `button` "Native", pressed `false`, disabled `true`; `button` "Aria", pressed `false`, disabled `true`; `button` "Enabled", pressed `false` | not observable | not observable |

### What the probes settle

- The toggle machine runs through `LineMachineController` unchanged. A controlled `pressed` round trip costs one host update per flip, and a property set from outside fires no `onPressedChange` (P1; D6).
- The machine does not guard `disabled`. The component must block activation itself whatever F5 decides (P1).
- Native `disabled` removes the chip from the tab order and stops user clicks before they reach the host in all three engines; `aria-disabled` keeps both, so the component must stop the click (P2; F2).
- Chromium names a button from its slot's fallback text when nothing is slotted, and slotted content replaces it (P2; F6 option (b)).
- Neither probe observes a screen reader. Firefox and WebKit exposure of the inner button stays unobserved (Phase 1 spec §6.C.4 notes, `:1180`; §12 AM-058).

## Part A — Requirements

### Overview

#### Description

`<line-chip>` is a compact toggle button for a category, a filter or a selection (PRD §4.1, `docs/PRD.md:252`). Each press turns it on or off. It renders a native `<button>` with `aria-pressed` inside its shadow root, so the platform keeps its keyboard, focus and accessibility behaviour (Phase 1 spec §10 SD31, `:2378`). The pre-built `@zag-js/toggle` 1.47.0 machine holds the pressed state (Phase 1 spec §6.C.4 C8 row, `:1164`; §10 SD11, `:2358`; ARCH §13.1, `docs/ARCHITECTURE.md:601`). Chip has no remove button, it is not compound, and it is not form-associated (SD11; C8 row). A user press fires `line-change` with the new state (F1). It carries no visual opinion beyond the `--line-chip-*` tokens, which resolve through the theme roles (PRD §9.11).

#### Use cases

- A filter bar above a list, where chips such as "In stock" and "Free shipping" each narrow the results and several can be on at once.
- Topic or category selection in a settings page, such as the subjects a user follows.
- A compact on/off option beside a list header, such as "Show archived".
- An htmx page that refreshes results on each toggle through `hx-trigger="line-change"` (F1).
- An agent-built filter on `<line-a2ui-surface>` from a `line` catalog `Chip` node whose `pressed` is bound to the data model (F1, F6; D1).

#### Anti-patterns

- An action that runs once, such as Save. Use `<line-button>` (`0002-button.md`).
- A formatting toggle in a toolbar, such as Bold. Use `<line-button pressed="false">` inside `<line-button-group>`, because Chip is separate from `Button[pressed]` by product role (Phase 1 spec §6.C.5, `:1215`; §10 SD35, `:2382`).
- A choice where only one option may be on. Use Radio Group or Toggle Group (PRD §4.2, `docs/PRD.md:280`, `:283`; Phase 2).
- A single setting that applies at once, such as dark mode. Use Switch (PRD §4.2, `docs/PRD.md:281`; Phase 2).
- A removable tag, such as an entered email address with a close control. Chip has no remove button (SD11); Tag Input covers it (PRD §4.5, `docs/PRD.md:330`).
- A read-only status label. Use `<line-badge>` (PRD §4.1, `docs/PRD.md:251`).
- An interactive control inside a chip, such as a link or a second button. The chip is a native `<button>`, and interactive content inside a button is invalid HTML (HTML Standard, the `button` element's content model) [INFERENCE: not probed].

#### User expectations

- Enter and Space flip the chip, and Tab reaches it unless it is disabled (APG Button, R8 `docs/research/01-research-accessibility.md:65`, `:69`).
- A screen reader announces the chip as a toggle button with its name and its pressed state.
- A disabled chip cannot be focused or pressed (F2; probe P2).
- Several chips in a row toggle on their own; turning one on leaves the others as they are.
- The pressed chip looks different from an unpressed one out of the box when the theme layer is loaded (F8).
- Inside a form, pressing a chip never submits or resets the form, and the chip adds nothing to the form data (C8 row; D10).

## Part B — Technical Specification

### Anatomy

```
<line-chip>                                     LineElement (not FormAssociated), shadowRootOptions.delegatesFocus = true
└── #shadow-root
    └── <button part="root" type="button">       role button; aria-pressed, disabled, aria-label, aria-description
        ├── <span part="indicator">              rendered only while pressed (F3)
        │   └── <slot name="indicator">
        ├── <slot name="prefix">
        └── <span part="label"><slot></slot></span>
```

- The inner `<button>` is always `type="button"`. It sits in the shadow tree, so it has no form owner, and the host is not form-associated, so nothing acts on a form (C8 row; D10).
- The role sits on the inner native `<button>` (Phase 1 spec §6.C.4 C8 row; §10 SD31). The host extends `LineElement` without the `FormAssociated` mixin (Phase 1 spec §6.C.2, `:987`), and `LineElement` still attaches `ElementInternals`, so `reflectState` writes `data-*` and `:state()` (ARCH §14.8, `docs/ARCHITECTURE.md:1190-1210`).
- The `indicator` and `label` parts take their names from the ARCH §5 vocabulary (`docs/ARCHITECTURE.md:315`, `:318`), and the `indicator` name matches the toggle anatomy part (`@zag-js/toggle` 1.47.0 `dist/toggle.anatomy.mjs:3`).
- The `indicator` wrapper and its slot are absent while the chip is off, so their content is neither rendered nor in the accessibility tree, as Button's `loading` part is (`0002-button.md` Anatomy; F3).
- The `prefix` zone is the slotted light-DOM element itself, as on Button, so the consumer styles it directly (`0002-button.md` Parts).
- ARCH §3 makes a leading icon a slot, because the consumer decides it (`docs/ARCHITECTURE.md:221-226`).
- The component renders none of zag's `data-scope`, `data-part` and `data-state` attributes on the inner button. Host reflection is the public state API (ARCH §14.8; D7).

### States

| Field | Value |
|-------|-------|
| Machine | `@zag-js/toggle` 1.47.0 `machine`, run through `LineMachineController` from `@websublime/line-core/machine` (ARCH §8, `:408`; §13.1, `:601`; Phase 1 spec §6.C.4 C8 row; §6.C.5, `:1216`; §10 SD11). The component imports no `@zag-js/vanilla` (Phase 1 spec §10 SD13) |

| State | Entered on | Left on | Host reflection |
|-------|------------|---------|-----------------|
| `idle` | start | — | — |

The machine has one state, `idle`, and keeps `pressed` in a bindable context (`dist/toggle.machine.mjs:10-34`; probe P1). `pressed` and `disabled` reflect on the host as flags (ARCH §14.8, `:1221`, `:1231`).

| Flag | Source | Host reflection |
|------|--------|-----------------|
| `pressed` | machine context `pressed`, which reads the `pressed` property while the bindable is controlled | `data-pressed`, `:state(pressed)` |
| `disabled` | `disabled` prop only; no `fieldset` source, because Chip is not form-associated | `data-disabled`, `:state(disabled)` |
| `focus-visible` | component state, set on the inner button's `focus` when it matches `:focus-visible` and cleared on `blur` (D2) | `data-focus-visible`, `:state(focus-visible)` (ARCH §14.9) |

**Machine wiring** (probe P1; D6)

- The props are the live function `() => ({ pressed: this.pressed, disabled: this.disabled, onPressedChange: this.#onPressedChange })`. `pressed` is always a boolean, so the bindable stays controlled and `defaultPressed` is never read (`node_modules/@zag-js/vanilla/dist/bindable.mjs:13`).
- `#onPressedChange(next)` sets `this.pressed = next` and then dispatches `line-change` with `{ value: next }`, the order Button uses (`packages/line-components/src/icon-button/icon-button.ts:142-151`). The surface reads the property when the event fires (`packages/line-genui/src/a2ui/projection.ts:609-617`).
- The component sends `PRESS.TOGGLE` on activation (F5). It never sends `PRESS.SET`, because a property set already reaches the machine through the live props (probe P1).
- The machine has no `disabled` guard, so the component checks `disabled` before it sends (probe P1; F5).
- `LineMachineController` signals each host update with `updateProps({})` (`packages/line-core/src/machine/line-machine-controller.ts:110-113`; Phase 1 spec §6.C.7, `:1260-1262`).
- If the machine fails to start, the controller sets `fallback` and the component renders the inner button from its own `pressed` and `disabled` with the same attributes; a click then flips `pressed` and fires `line-change` directly, so the chip still works (MANIFESTO Law 9; probe P1) [INFERENCE: the fallback flip path is not probed].

### Slots

| Slot | Kind | Accepts |
|------|------|---------|
| `(default)` | `ComponentId` | the label, usually text; on the agent path the surface writes the `label` text here (F6) |
| `prefix` | `ComponentId` | a leading icon, usually one decorative `<line-icon>`; hand-written markup only, outside the descriptor slot map, as Button's `prefix` (`0002-button.md` AM-005) |
| `indicator` | `ComponentId` | a pressed mark, usually a decorative check `<line-icon>`; rendered only while pressed; hand-written markup only, outside the descriptor slot map (F3) |

- A `<line-icon>` with no `aria-label` is decorative (`0014-icon.md` decision D1), so neither the prefix icon nor the indicator joins the name.
- Chip has no trailing slot. A trailing zone invites a remove control inside the button, which SD11 excludes and HTML forbids (F3).

### Props

| Property | Attribute | Type | Default | Reflects | Description |
|----------|-----------|------|---------|----------|-------------|
| `pressed` | `pressed` | `boolean` | `false` | yes | whether the chip is on; a user press flips it and fires `line-change` (D5) |
| `disabled` | `disabled` | `boolean` | `false` | yes | removes the chip from the tab order and blocks activation (F2) |
| `ariaLabel` | `aria-label` | `string \| null` | `null` | yes | copied to the inner button, where it names the role (C5) |
| `ariaDescription` | `aria-description` | `string \| null` | `null` | yes | copied to the inner button (C5) |

- `pressed` is a boolean attribute (D5). A present attribute means `true`, except the value `"false"`, which parses to `false`, as Button's converter does (`packages/line-components/src/button/button.ts:48-51`). The property reflects as an empty attribute when `true` and removes it when `false`. The default `false` leaves no attribute (Lit `useDefault: true`), and an author's `pressed="false"` stays as written until the property changes.
- `ariaLabel` and `ariaDescription` are Lit properties on the `aria-label` and `aria-description` attributes, as on Button and IconButton (`button.ts:107-108`; `icon-button.ts:71-72`).
- No `variant` (F4). No `type`, `name`, `value`, `form*` or `custom-validity`, because Chip is not form-associated (C8 row; ARCH §17.2 C4 applies to §7 components only, `docs/ARCHITECTURE.md:398`).

### Events

| Event | `detail` type | Fires when |
|-------|---------------|------------|
| `line-change` | `LineChipChangeDetail`, `{ value: boolean }` | **Commit event (C9; F1).** A user activation flipped `pressed`; `detail.value` is the new state. It bubbles and is not composed. It fires after the property has changed. It never fires when `pressed` changes through the property or the attribute, nor for a blocked activation, focus or hover (probe P1) |

- Activation means a `click` that reaches the host while the chip is not disabled. A pointer click, Enter or Space on the inner button, and `host.click()` all count (F5).
- The host flips the chip after the `click` dispatch ends and only when no listener called `preventDefault()`, as Button does (`icon-button.ts:187-196`; F5).
- While `disabled`, Chip stops a `click` that reaches the host in the capture phase, so no bubble listener on the host or its ancestors receives it (`icon-button.ts:171`, `:187-191`; F5). Probe P2 shows a user click never reaches a host whose inner button is natively disabled; the capture stop covers `host.click()` and a click on the host box outside the inner button [INFERENCE].
- No `line-input`, because a toggle has no live edit (ARCH §17.2 C3, `docs/ARCHITECTURE.md:1574`).
- The class JSDoc carries `@fires {CustomEvent<LineChipChangeDetail>} line-change`.

- The tokens and their defaults are orchestrator default D8. `--line-radius-round` is `1e5px` (`packages/line-tokens/src/radii.css:15`), `--line-size-6` is `1.75rem` (`sizing.css:15`), and the colour aliases are the PRD §9 Radix steps (ARCH §4, `docs/ARCHITECTURE.md:243`; `packages/line-themes/src/aliases.css:10-28`).
- `:host` declares the tokens (PRD §9.11). Under F8 (b), `:host([data-pressed])` redeclares the defaults of the three colour tokens and adds no other rule.
- `root` sets the border longhands (`border-style: solid`, `border-width`, `border-color`), not the shorthand, so an invalid `var()` cannot reset `border-style` to `none` (`0006-alert.md` CSS custom properties).
- Without `line-themes` the colour tokens are invalid at computed-value time, so `root` has a transparent background, its border takes `currentColor` and the text inherits its colour (`0006-alert.md` AM-002). An unpressed and a pressed chip then look the same, and only the `indicator` slot or consumer CSS tells them apart.
- The focus ring and, under F8 (b), the pressed colours are the only state styles. Hover, active and disabled carry no styles, as on Button (`0002-button.md` AM-008). `:hover` and `:active` match the host natively, so Chip reflects no `hovered` or `active` (ARCH §14.8, `docs/ARCHITECTURE.md:1240`; D4).
- `::part(root)` takes `inline-size: 100%` and fills its host, as Button's does (`0002-button.md` AM-010; D9).

### Keyboard

| Key | Action |
|-----|--------|
| `Tab` / `Shift+Tab` | moves focus to or from the inner button; skips a disabled chip (probe P2) |
| `Enter` | flips `pressed` and fires `line-change`, through the native button's `click` |
| `Space` | flips `pressed` and fires `line-change` on keyup, through the native button's `click` |

The keys are those of the APG Button pattern (R8 `:65`), handled by the native button. Chip adds no key handler. Arrow keys do nothing, because Chip has no group semantics (D3).

### A11y

| Field | Value |
|-------|-------|
| Role | `button` on the inner native `<button part="root">` (Phase 1 spec §10 SD31; §6.C.4 C8 row; §7.4, `:2125`) |
| ARIA attributes | `aria-pressed="true\|false"` from the machine context; `aria-label` and `aria-description` copied from the host; native `disabled` while disabled (F2) |
| Accessible name | the slotted content in tree order (indicator while pressed, prefix, label), or the host `aria-label` copied to the inner button, which wins (C5). Decorative icons add nothing (`0014-icon.md` D1) |
| Focus | `delegatesFocus: true`, so `host.focus()` focuses the inner button (`0002-button.md` A11y); `data-focus-visible` on the host for keyboard focus only (ARCH §14.9; D2) |

- The host stays a role-less `generic` element and keeps the author's `aria-label`. Chromium exposes it as a named `generic` node, and axe-core 4.14.0 reports no violation for that case (`0002-button.md` A11y; `0003-icon-button.md` A11y).
- A chip keeps one label in both states, because `aria-pressed` carries the state (`0003-icon-button.md` A11y, "Toggle label") [INFERENCE: APG Button guidance, not quoted in R8].
- Chip sets no role or ARIA state through `ElementInternals`. Its internals carry only the custom states of `reflectState`, so the Chromium CDP assertion and `INTERNALS` read-back that Phase 1 spec §6.C.4 requires for internals-only roles do not apply (`:1180`; §12 AM-058).
- **Screen-reader check.** A Playwright `ariaSnapshot` in the Browser tier, in chromium, firefox and webkit, records one `button` node per host with the expected name and pressed state, as Button's does (`packages/line-components/__tests__/integration/button/button.e2e.ts`). Playwright computes the snapshot itself, so it does not show what each engine exposes. A Chromium CDP read of the inner button's `pressed` and `disabled` properties backs it (probe P2). A manual screen-reader pass is optional and never blocks the row (Phase 1 spec §12 AM-058).
- **Firefox and WebKit gap.** No check proves what Firefox and WebKit expose to assistive technology for the copied name and the pressed state. The gap is recorded here (Phase 1 spec `:1180`; §12 AM-058).
- **A set of chips.** Chip adds no group role. The docs show a filter bar wrapped in an element with `role="group"` and an `aria-label` (D3).

### Agent contract

### F1 — Value-bearing

**Evidence.** ARCH §17.2 C3 makes a component value-bearing when its descriptor binding map names a value prop (`docs/ARCHITECTURE.md:1574`). The Phase 1 spec leaves the choice to this spec (C8 row, `:1164`), and plan §2.4 says Chip is value-bearing only if its binding map names one (`docs/plans/01-plan-core-primitives.md:174`). Button and IconButton name `pressed` with commit event `line-change` (`packages/line-genui/src/catalog/descriptors/button.ts:40`; `icon-button.ts:40`). A2UI basic `CheckBox` binds its on/off state as `value` (`DynamicBoolean`, `packages/line-genui/__tests__/fixtures/a2ui-v0_9_1/basic_catalog.json:585-592`). The surface writes the element's property back to a bound prop when the commit event fires (`projection.ts:597-622`). Probe P1 shows `line-change` fires once per flip and never on a property set.

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** Value-bearing | binding map `value: { prop: 'pressed', commitEvent: 'line-change' }`; `line-change` with `{ value: boolean }` is the C9 commit event | An agent's bound `pressed` follows the user; htmx triggers on `line-change`; the htmx row runs (b), (c) and (d), and (a) is `n/a` because Chip is not form-associated. Same contract as Button and IconButton |
| (b) Not value-bearing | no value prop and no commit event; Chip fires no `line-change` | C9 and the htmx row become `n/a`. A consumer learns of a flip only from `click`, which fires before the flip under F5 (a), so it must read `pressed` a task later; an agent's bound `pressed` never learns the user's choice |

### F2 — Disabled form

**Evidence.** The toggle `connect()` renders native `disabled` (`dist/toggle.connect.mjs:17`). Probe P2 shows native `disabled` leaves the tab order and stops user clicks before the host in all three engines, while `aria-disabled` keeps the chip focusable and lets clicks through; Chromium marks both `disabled`. Button and IconButton use native `disabled` and keep focus only while `loading` (`0002-button.md` Props). R8 lists `aria-disabled` for an unavailable button (`docs/research/01-research-accessibility.md:65`).

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** Native `disabled` | the inner button gets `disabled`; Tab skips the chip | Button parity and the zag default; nothing to stop for user clicks. A keyboard user cannot discover why a filter is unavailable |
| (b) Focusable `aria-disabled` | the inner button gets `aria-disabled="true"` and no `disabled`; Tab reaches it | Discoverable in a filter bar. The component overrides `connect()`, stops every click itself (P2), and differs from Button |

### F3 — Anatomy

**Evidence.** ARCH §3 makes consumer-controlled zones slots (`docs/ARCHITECTURE.md:221-226`), Button uses `prefix` and `suffix` slots (ARCH §13.1, `:596`), and ARCH §5 lists `indicator` and `label` (`:315`, `:318`). The toggle anatomy has `root` and `indicator` (`dist/toggle.anatomy.mjs:3`), and `getIndicatorProps()` gives the indicator `data-state` (probe P1). SD11 excludes a remove button, and a nested interactive control inside the native button is invalid HTML [INFERENCE: not probed]. Button renders its `loading` part only while loading (`0002-button.md` Anatomy). Agents cannot fill slots outside the descriptor slot map (`0002-button.md` AM-005).

| Option | Anatomy | Consequence |
|---|---|---|
| (a) **Recommended.** Default, `prefix` and `indicator` slots; `indicator` part only while pressed | `root` > (`indicator` part > `indicator` slot, while pressed) + `prefix` slot + `label` part > default slot | A consumer slots a check icon once and it shows only when on, with no CSS; the indicator joins the name only if it is a named icon. Layout shifts by the indicator's width on a flip |
| (b) As (a), `indicator` part always rendered | the wrapper stays and carries `data-state`; the consumer hides it off through `line-chip:not([data-pressed])::part(indicator)` | No layout shift if the consumer reserves the space; one slot cannot show two glyphs, so a plus/check swap needs two slots |
| (c) As (a) plus a `suffix` slot | a trailing slot for a count or an icon | Symmetry with Button. Invites a remove button inside the chip, which SD11 excludes |
| (d) Default and `prefix` slots only, no `indicator` | no indicator part | Smallest surface. The pressed state shows only through tokens (F8) or consumer CSS |

### F4 — Variants

**Evidence.** C6 permits a closed enum that changes only the component's own token defaults (`docs/ARCHITECTURE.md:1577`). The PRD row names no variant (`docs/PRD.md:252`), and A2UI has no chip type to mirror (D1). Button's `variant` mirrors A2UI basic `Button` (`0002-button.md` Variants).

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** None | no `variant` attribute | Smallest API; the pressed state is the visual axis (F8). A consumer who wants an outlined and a filled family sets tokens per class |
| (b) Emphasis enum such as `variant="default \| primary"` | `primary` redeclares the colour tokens | Mirrors Button's vocabulary. A chip's emphasis comes from its state, so two axes (variant and pressed) multiply the token combinations and the visual baselines |
| (c) Shape enum such as `variant="outline \| soft"` | `outline` keeps a transparent background and a border; `soft` fills the background | Common chip styles. A new vocabulary no other line component uses |

### F5 — Activation path

**Evidence.** Button and IconButton listen for `click` on the host in the capture phase, stop it while not interactive, and send `ACTIVATE` in a later task unless a listener called `preventDefault()` (`icon-button.ts:171`, `:187-196`; `0002-button.md` Events). The toggle `connect()` offers an `onClick` for the inner button that checks `defaultPrevented` and `disabled` when it runs (`dist/toggle.connect.mjs:22-26`). `send` is queued on a microtask (probe P1). `host.click()` dispatches on the host and never reaches the inner button [INFERENCE: DOM dispatch rule, not probed for Chip].

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** Button's host-level path | a capture `click` listener on the host stops the click while `disabled`; otherwise, after the dispatch ends and unless `defaultPrevented`, it sends `PRESS.TOGGLE` | Same behaviour as Button and IconButton; `host.click()` flips the chip; any listener, on the host or an ancestor, can cancel a flip. `line-change` lands a task after the `click` |
| (b) The zag `onClick` on the inner button | the inner button's `click` listener runs `getRootProps().onClick`; the component adds the capture stop for `host.click()` while disabled | Uses the machine package as written; the flip lands one microtask after the inner listener. `host.click()` does not flip the chip, and only a listener inside the shadow root or a capture listener can cancel a flip |

### F6 — Agent label text

**Evidence.** The `line` catalog descriptors are Alert, Button, ButtonGroup, Icon, IconButton, Separator and Stack, with no `Text` (`packages/line-genui/src/catalog/index.ts:103-111`). The surface counts `childText` only for basic-catalog `Text` (`projection.ts:160-175`), so a `line` catalog `child` yields no visible text (`0003-icon-button.md` Descriptor fields). A2UI basic `CheckBox` carries its visible text as a `label` `DynamicString` (`basic_catalog.json:585-588`). MANIFESTO Law 4 prefers slots over props for content (`docs/MANIFESTO.md:45`). The descriptor name sources are `childText` and `accessibilityLabel` (`descriptor.ts:128-130`), and the binding kinds are attribute, property and surface lookup (`descriptor.ts:84-104`). Chromium names a button from its slot's fallback text (probe P2). A descriptor with no slot map skips the surface's child reconciliation (`projection.ts:462-464`).

| Option | What it decides | Consequence |
|---|---|---|
| (a) Button parity | `child` (`ComponentId`) into the default slot; name from `accessibility.label` | No genui change. An agent Chip shows no visible text, only an accessible name, so a filter bar of agent chips is a row of empty pills |
| (b) Component `label` attribute | Chip gains a `label` property rendered as the default slot's fallback content; the descriptor binds `label` → attribute; a new name-source kind reads the prop | Visible text on the catalog and tool paths; slotted content still wins (probe P2). Adds a content prop to the component, which Law 4 discourages, and a genui name-source kind (Phase 1 spec §6.G.1, §6.G.4 `AM-nnn` before code) |
| (c) **Recommended.** Surface text binding | the descriptor's `label` (`DynamicString`) binds through a new kind that sets the host's text content, so the text lands in the default slot; no `child`; a new name-source kind reads the prop | Visible text on both paths, and the component keeps a slot-only API (Law 4). The same binding could later give a `line` catalog Button visible text. Needs two genui contract additions (Phase 1 spec §6.G.1, §6.G.4 `AM-nnn` before code) and widens the C8 PR into `line-genui/src/a2ui/` |
| (d) Defer | (a) now, and a new row adds a `line` catalog `Text` descriptor | No contract change in C8. Agent chips stay text-less until that row lands |

### F7 — Agent action

**Evidence.** A2UI basic `CheckBox` has no action, and its state travels through the `value` binding (`basic_catalog.json:567-597`). Button and IconButton bind `action` → `click`, marked native (`descriptors/button.ts:42`). Under F5 (a), the flip and the write-back land after the `click` dispatch, so an action resolved during `click` sees the old data-model value [INFERENCE: the action's resolution time is not probed]. The surface registers one listener per element and event name (`projection.ts:624-633`), and it wires actions before the commit event (`projection.ts:449-458`), so an action bound to `line-change` would suppress the commit write-back.

| Option | What it decides | Consequence |
|---|---|---|
| (a) **Recommended.** None | no `action` prop; the agent reads the bound `pressed` | CheckBox parity; no stale value. An agent that wants to react at once must watch its data model, or the app sends the next action from another control |
| (b) `action` → `click`, native | Button parity | The agent hears each press, but the action may carry the value from before the flip; the description then names `action`, so the descriptor needs a tool description |
| (c) `action` → `line-change` | the action fires after the commit | The action sees the new value. The surface's per-event listener dedup drops the write-back, so `projection.ts` must change first |

### F8 — Pressed look

**Evidence.** Button and IconButton keep `pressed` headless and draw only the focus ring (`0002-button.md` AM-008; ARCH v0.8.23, `docs/ARCHITECTURE.md:22-24`). C6 limits variants to token defaults and says nothing about states (`:1577`). Button Open Question 11 gave variants token defaults because otherwise "the agent's emphasis reached the user as nothing and the variant baselines were identical" (`0002-button.md`). The pressed state is the chip's main signal, and the agent path cannot fill the `indicator` slot (F3).

| Option | What it decides | Consequence |
|---|---|---|
| (a) Headless | no pressed rule; docs and the Styled states story show `[data-pressed]` and `:state(pressed)` | Button parity. Out of the box, an agent chip that is on looks the same as one that is off, and the Default and Pressed baselines match |
| (b) **Recommended.** Pressed token defaults | `:host([data-pressed])` redeclares `--line-chip-bg`, `--line-chip-color` and `--line-chip-border-color` to the accent `-bg`, `-text` and `-border` aliases, and adds no other rule | With the theme layer a pressed chip is visibly on, and the baselines differ. A state style beyond the focus ring, which Button rejected for its own states; without the theme both states still look the same |
| (c) Indicator only | (a), plus the docs recommend the `indicator` slot | No style rule. Agents get no visible state, because they cannot fill the slot |
