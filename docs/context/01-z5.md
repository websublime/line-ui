## Understanding
- Outcome: every test reaches another workspace package through its package name and a declared dependency,
  and reaches its own package's build output through its own `exports`. A broken `exports` entry or an
  undeclared edge then fails a test.
- Stated:
  - Relative resolution into another package is wrong; such packages are declared devDependencies.
  - Tests stay as close as possible to what ships.
- Observed on `6fb61d3`:
  - Bun installs workspaces in isolated mode. From a package's `__tests__/`, only declared packages resolve by
    name. Probes (`import.meta.resolve`, Node and Bun) failed for `@websublime/line-tokens` from `line-themes`
    and for `line-colors` and `line-themes` from `line-tokens`.
  - Self-reference works. `@websublime/line-themes` resolves to its own `dist/index.css` from
    `packages/line-themes/__tests__/` (Node and Bun).
  - Eight files resolve by relative path into a `dist`:
    - `line-themes/__tests__/aliases-scope.e2e.ts:31`: `line-colors` and its own dist
    - `line-themes/__tests__/cascade-layer.e2e.ts:19`: `line-tokens` (undeclared), `line-colors` and its own dist
    - `line-themes/__tests__/hue-role-names.e2e.ts:33`: `line-colors` and its own dist
    - `line-themes/__tests__/palette.snapshot.test.ts:24`: `line-colors`
    - `line-themes/__tests__/schema.test.ts:43-44`: `line-colors` and its own dist
    - `line-themes/__tests__/role-mapping.snapshot.test.ts:24`: its own dist
    - `line-tokens/__tests__/shadows.e2e.ts:39-41`: `line-colors` and `line-themes` (both undeclared) and its own dist
    - `line-core/__tests__/integration/htmx/htmx-harness.ts:103-113`: `node_modules/htmx2|4` at the repo root
  - Layers (PRD §6.1): `line-tokens` L0, `line-colors` L1, `line-schemas` L2, `line-themes` L3. Declaring what
    `shadows.e2e.ts` reads makes `line-tokens` point up at L1 and L3, and with `cascade-layer.e2e.ts` it forms a
    devDependency cycle `line-tokens` ↔ `line-themes`. `lint-layers` ignores devDependencies
    (`scripts/lint-layers.mjs:13-16`). A Bun 1.4.3 probe ran `--filter` builds over such a cycle with no error
    and picked an order on its own.
  - The htmx harness is a shared helper "that component suites reuse" (Phase 00 spec AM-063). A `line-components`
    suite can reach it today only by a relative path into `line-core`, which the rule forbids.
  - `htmx2` and `htmx4` are root devDependencies. Only `line-core` uses them, in the harness and in the
    `__experimental__/htmx/example/server.ts` spike.
  - `lucide-static` and `@phosphor-icons/core` are optional peers of `line-icons`. Bun links them into
    `packages/line-icons/node_modules`, so the `line-icons` tests already resolve them through declared entries.
  - The auto-pair test `line-themes/__tests__/auto-pair.behaviour.test.ts` string-matches `src/defaults.css`
    for amber and violet only. PRD §5.2.1 (`docs/PRD.md:539`) asks that "each" auto-pair selector resolve to
    the documented gray (PRD §9.5 table). Phase 00 spec §6.C.7 narrowed it to four cases.
- Assumed (orchestrator defaults, open to Miguel):
  - Third-party packages that tests use come from the root `devDependencies`, the shared test tooling (Phase 1
    spec §6.G.2). A package declares a third-party package that its own non-test code resolves, as `line-testing`
    and `line-core` do with `htmx2` and `htmx4`. The first wording ("a third-party package that only one
    package's tests use is declared by that package") would have reversed SD96 and the G2/G3 root

## Acceptance criteria
- No test under `packages/*/__tests__/` or `apps/*/__tests__/` resolves a path inside another package, or inside
  its own `dist/`, by a relative path. A grep over the test files proves it.
- Every workspace package a test resolves is declared in the manifest of the test's package, and every
  test-only devDependency between design-system packages points down the layer order.
- `bun test`, `bun run e2e` (all projects) and the visual project pass. `lint-layers`, `verify-pack` and
  `bun install --frozen-lockfile` pass.
- The auto-pair browser test covers all 31 accents against PRD §9.5 in Chromium, Firefox and WebKit.
- The htmx harness lives in `@websublime/line-testing`, and `line-core`'s harness self-test imports it by name.
- The rule is written in PRD §5.2 and Phase 1 spec §7.8, and Phase 1 spec §6.C.4, §10 SD86 and the ledger C
  rows carry Z5 as a dependency.
