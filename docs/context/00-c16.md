## Understanding
- Outcome: the Radix `gray` hue ships as `neutral`. Every hue and every role becomes addressable in every scope,
  and `neutral` works as an accent and as a gray.
- Evidence (Chromium, built CSS of `0.1.0`):

  | `<html>` attributes | `--line-gray-1` | `background: var(--line-gray-1)` |
  |---|---|---|
  | none | slate value `light-dark(#fcfcfd,#111113)` | slate, not the gray hue `#fcfcfc` |
  | `data-gray="gray"` | invalid | transparent |
  | `data-accent="gray"` | invalid | transparent |

  `gray/gray.css` and the `[data-accent="gray"]:not([data-gray])` block in `defaults.css` declare
  `--line-gray-N: var(--line-gray-N)`, a self-reference cycle. Every other gray-role mapping on an element
  overrides the hue's own `--line-gray-N` there.
- Stated (Miguel): rename the hue; the role keeps `--line-gray-*` and `data-gray`; the new hue name is `neutral`.
- Assumed (orchestrator defaults, Miguel may correct):
  - The generator reads the Radix objects `gray`, `grayA`, `grayP3`, `grayP3A` and their `Dark` variants, and
    emits them under the name `neutral` through an explicit source-to-emitted name map for this one hue.
  - No compatibility alias for the old hue tokens; an alias would recreate the collision. Clean cutover.
  - `neutral` self-pairs in the auto-pair table; the default gray stays `slate` (PRD §9.5).
    `PER_HUE_CONTRAST.neutral` is `#fff`, as `gray` was.
  - Changesets are `patch` for `line-colors`, `line-schemas` and `line-themes` (PROCESS §6, Phase 00 after
    `0.1.0`). Risk: consumers on `^0.1.0` receive a rename in a patch. The summary names the rename. Theming with
    `gray` was already broken, and the direct hue tokens worked only without `line-themes`.
  - `apps/storybook` stays untouched here (row `00-F12` edits `preview.ts` in parallel and builds its menus from
    `GRAY_HUES`). Merge `00-F12` before `00-C16`, or the old addon default `gray` points at a removed hue.

## Acceptance criteria
1. PRD v0.8.10 records the decision. PRD, ARCHITECTURE, plan and spec name the hue `neutral`. Spec `AM-052`
   (trigger `decision`) aligns §4.2, §4.4, §6.C.1, §6.C.3, §6.C.4, §6.C.7 and §9.2. These land in one commit. A
   hue-specific grep for the old name (`--line-gray-` as a hue, `line-colors/gray`, `gray.css` in `line-colors`,
   `data-accent="gray"`, `data-gray="gray"`, `gray` in hue lists) returns zero live hits.
2. `line-colors` emits `neutral.css` (`--line-neutral-*`) and no `gray.css`; its exports map and `index.css`
   follow.
3. `HUES` and `GRAY_HUES` list `neutral`, not `gray`; `PER_HUE_CONTRAST` follows.
4. `line-themes` emits `accent/neutral.css` and `gray/neutral.css`; no file declares a role token that references
   itself.
5. A real-browser regression test, driven by the schema lists, fails on `0.1.0` and passes after: for every
   `GRAY_HUES` entry the gray role equals that hue's palette; for every `HUES` entry used as accent the accent
   role equals that hue's palette; and with `line-themes` loaded each hue's `--line-{hue}-1` keeps its own
   palette value.
6. `verify-palettes-fresh` and `validate-contrast` pass; snapshots regenerate; Verify record green
   (`bun run lint`, `bun run build`, `bun test` for each touched package, `bun run e2e`).
7. `patch` changesets for the three packages name the rename.

## Affected packages and apps

  and their tests. The layer rule is unchanged (schemas → colors → themes).

## Public surface touched
- Hue tokens `--line-gray-{1..12, a1..a12, contrast}` become `--line-neutral-*`.
- Exports `@websublime/line-colors/gray` becomes `/neutral`; `@websublime/line-themes/accent/gray` and
  `/gray/gray` become `/accent/neutral` and `/gray/neutral`.
- Attribute values `data-accent="gray"` and `data-gray="gray"` become `"neutral"`.
- Types `Hue` and `GrayHue` lose `gray` and gain `neutral`.
- The gray role (`--line-gray-*`, its aliases, `data-gray`) is unchanged.

## Spec drift found
- §6.C.4 generates `--line-gray-1: var(--line-{G}-1)` with `G = gray`, a cycle. The collision sits in PRD §9.2
  (hue tokens `--line-{hue}-{step}`) against §9.6 (role tokens `--line-{role}-{step}`).
