## Understanding
- Outcome: consumers get one documented way to switch light and dark, the `color-scheme` property, and every
  document that names a mode switch matches what the packages ship.
- Evidence:
  - `docs/PRD.md:1428` says consumers toggle mode with `style.colorScheme` on `<html>` "or via `.dark` / `.light`
    classes on `<html>`". The sentence dates from the initial import (`939cad2`).
  - No file under `packages/*/src` declares `.dark`, `.light` or `color-scheme`. A consumer who adds
    `class="dark"` to `<html>` sees no change.
  - No package sets `color-scheme`, so `light-dark()` returns the light value until the consumer sets it.
  - ARCHITECTURE §4 (`docs/ARCHITECTURE.md:191`) names `light-dark()` and `color-scheme`. Plan §4.7 G2
    (`docs/plans/00-plan-design-system.md:198`) says "light/dark" and names no mode class.
    ARCHITECTURE v0.8.0 replaced class-based theming with `data-*` attributes.
  - The shipped theming guide (`apps/storybook/stories/theming.mdx:87-107`) teaches the meta tag,
    `:root { color-scheme: light dark }` and `style.colorScheme`. It never mentions the classes.
  - `docs/specs/00-spec-design-system.md:699` (§6.C.2) says `shadows.css` uses neither `prefers-color-scheme` nor
    the classes.
  - MANIFESTO Law 2 requires the `line-` prefix on every public surface we author and exempts standard hooks such
    as `data-*`. Bare `.dark` and `.light` rules in a line package would break the law.
  - Tailwind CSS v4 drives its `dark` variant from a `.dark` class or a `data-theme` attribute on an ancestor
    (https://tailwindcss.com/docs/dark-mode). Neither sets `color-scheme`, so a Tailwind page maps its class to
    line tokens with one consumer rule, `.dark { color-scheme: dark }`.
- Stated (Miguel):
  - `color-scheme` is the only mode switch. No package declares a mode class or attribute.
  - The shadow scale switches through `light-dark()` alone (AM-054).
- Assumed (orchestrator defaults, Miguel may correct):
  - PRD §9.8 names the three ways to set `color-scheme` (meta tag, CSS declaration, `style.colorScheme`) and the
    one-rule mapping for a consumer class such as Tailwind's `.dark`.
  - Spec §6.C.2 drops the clause about the classes, because the classes no longer exist anywhere.
  - ARCHITECTURE, the plan, the theming guide and `CLAUDE.md` stay as they are, because none names a mode class.
    ARCHITECTURE §4 and the theming guide name `color-scheme` as the switch. The plan and `CLAUDE.md` say
    "light/dark" only.
  - No published package changes, so the branch carries `bun run empty`.
