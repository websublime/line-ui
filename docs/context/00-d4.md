## Understanding
- Outcome: every `LineElement` knows its resolved text direction (`'ltr' | 'rtl'`), re-renders when it changes,
  and component CSS can target RTL. The resolved value is also what `LineMachineController` consumers pass to
  Zag machines (`dir?: "ltr" | "rtl"` in `@zag-js/types`).
- Stated (spec §6.D.4):
  - reflect the document/computed `dir` into a host property `dir` typed `'ltr' | 'rtl'`;
  - observe with `MutationObserver` on `documentElement` only; hosts do not observe themselves;
  - expose `this.dir` to templates and to `:host([dir="rtl"])` selectors.
- Stated (code): `packages/line-core/src/mixins/direction.ts` is the D1 identity stub; its path, export name
  and signature `DirectionMixin<T extends Constructor<LitElement>>(Base: T): T & Constructor<LitElement>` stay
  stable. `LineElement` composes `DirectionMixin(MetadataMixin(InspectorMixin(LitElement)))`.
- Assumed: one shared module-level observer, not one per instance (spec silent; perf default).

## Spec drift found
Probe (throwaway Playwright script, Chromium 148, Firefox 150, WebKit 26.4): a `<div dir="rtl">` inside
`<html dir="ltr">` wraps two hosts; host `b` carries `dir="ltr"`.

| Observation | Chromium | Firefox | WebKit |
|---|---|---|---|
| Host `a` (no attribute): computed `direction`, `:host(:dir(rtl))` applied | rtl, yes | rtl, yes | rtl, yes |
| Host `b` (`dir="ltr"` on host): computed `direction` | ltr | ltr | ltr |
| Wrapper flipped to `ltr`, no JS: host `a` re-styles | yes | yes | yes |

1. **Reflection overrides native inheritance.** The `dir` attribute on the host sets the host's own
   directionality (HTML spec). If the mixin writes the document's `dir` onto the host, a host inside an RTL
   region of an LTR document is forced LTR (host `b` row). That breaks the PRD's "natively via `dir`" contract.
2. **`documentElement`-only observation misses nested regions.** An ancestor `dir` change below `<html>` is not
   seen, so the reflected value goes stale and keeps pinning the wrong direction.
3. **Self-pinning.** After the mixin writes `dir="rtl"` on the host, an ancestor walk that starts at the host
   finds its own attribute; the mixin must track which writes were its own versus author-set.
4. **Native `HTMLElement.dir` shadowed.** `el.dir` is a platform accessor that returns the attribute value (`""`
   when unset, `"auto"` allowed). Redeclaring it as a Lit property typed `'ltr' | 'rtl'` changes what
   consumers and frameworks read and write.
5. **`dir="auto"`** is valid HTML and outside the spec's `'ltr' | 'rtl'` type; the spec does not say how it
   resolves.

Fact checked: `:host(:dir(rtl))` works and tracks ancestor changes live in all three target engines (PRD:
latest 2 stable of Chrome, Firefox, Safari).

## Decisions (Miguel, 2026-10-01)
- **Direction source and CSS hook: native-first (option B over A).** The mixin never writes the host `dir`
  attribute. Component CSS targets RTL with `:host(:dir(rtl))`. The resolved value comes from
  `this.matches(':dir(rtl)')`, recomputed on connect and on one shared module-level `MutationObserver` on
  `document` (`subtree: true, attributeFilter: ['dir']`). Rejected A: reflecting the document `dir` onto the
  host and observing `documentElement` only, which forces nested RTL regions to LTR. Known limit: `dir`
  changes on ancestors inside other shadow roots are not observed.
- **Property name: new read-only `direction: 'ltr' | 'rtl'`.** The native `HTMLElement.dir` stays untouched.
  Rejected: overriding `dir`.
- **`dir="auto"`: delegated to the engine via `:dir()`.** The JS value and the `:dir()` CSS stay coherent.
  Known limit: a text change under `dir="auto"` (no attribute change) does not trigger a recompute. Rejected:
  treating `auto` as `ltr`.
