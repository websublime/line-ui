## Understanding
- Outcome: `@websublime/line-components/center` registers `<line-center>`, a Static layout container that centres
  its content on one or both axes, with `agentExposed: true` and a `Center` descriptor in the `line` catalog.
- Stated:
  - PRD §4.1 (`docs/PRD.md:265`): Static, "Centering utility for horizontal, vertical, or both axes".
  - Phase 1 spec row C18: Static, tag `line-center` at `./center`, role settled by the component spec from R8 §2.2,
    not form-associated, `agentExposed: true`, htmx `n/a` expected.
  - R8 (`docs/research/01-research-accessibility.md:82`): no role, no name, no keyboard.
  - Miguel's decisions, 2026-11-16, each the recommended option of `0020-center.md`:
    - F1 (a): `axis="both | horizontal | vertical"`, default `both`, on logical axes.
    - F2 (a): the host is a column flex container; `justify-content` and `align-items` centre it.
    - F3 (a): no inline display; the docs show `line-center:not([hidden]) { display: inline-flex }`.
    - F4 (a): content centring only, with no width cap.
    - F5 (a): several children form one centred column in source order, with no gap.
    - F6 (a): `axis` and a single `child` (`ComponentId`) reach agents, in the `line` catalog only.
    - F7 (a): `hostNaming: never`; the Center tool carries no accessibility parameters (Phase 1 spec AM-102).
    - F8 (a): `safe center`, so oversized content aligns to its start edge.
    - F9 (a): the consumer or a stretching parent supplies the height.
    - F10 (a): Center sets no `text-align`.
  - Miguel, 2026-11-16: the defaults D1–D20 stand as drafted.
- Observed (spec-draft probes P1–P12, Playwright 1.64.0 on chromium 156, firefox 157 and webkit 27.2, happy-dom,
  htmx 2.0.11 and 4.0.0, axe 4.14.0; recorded in `0020-center.md` Probes):
  - A role-less host adds no node to the Chromium accessibility tree; a labelled one is a named `generic`, and axe
    is silent about it (P1).
  - With several children, column flex keeps them together, while `place-items` spreads them over the height (P2).
  - Plain `center` cuts off the start of oversized content where no scroll reaches; `safe center` does not (P3).
  - `min-block-size: 100%` overflows a parent by any sibling's height (P4).
  - No A2UI basic type in v0.9 or v0.9.1 centres content (P10); none of the seven competitor libraries ships a
    Center element (P11).
- Assumed: none beyond defaults D1–D20.
