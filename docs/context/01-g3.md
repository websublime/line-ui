## Understanding
- Outcome: `frontendTools(descriptors, provider)` in `@websublime/line-genui/catalog` emits one flat
  `{name, description, parameters}` tool per agent-exposed descriptor for OpenAI strict, Anthropic strict and
  Gemini. Each tool description reads correctly against that tool's own parameters.
- Stated:
  - Spec §6.G.3 states the walker and the provider serialisations.
  - Miguel's defaults, 2026-11-04:
    - The accessibility parameters follow `accessibility.hostNaming.kind`.
    - The G3 docs go in `packages/line-genui/README.md`.
    - An optional descriptor field overrides the tool description.
    - `properties` gets a null prototype.
    - A prop named `accessibilityLabel` or `accessibilityDescription` is an error.
  - Decide, 2026-11-04. Miguel confirmed the orchestrator defaults and added the PRD:
    - The field is `toolDescription?: string`. When it is absent, the tool takes `description`.
    - Button, Separator and Stack set the field; Icon does not.
    - A test fails when an emitted tool description names, in backticks, a left-out prop or `accessibility.*`.
    - One `docs(spec)` commit, before the code, aligns every document:
      - PRD §8.1 field list, with revision-log entry v0.8.30;
      - ARCH §17.3 field list, v0.8.22;

## Acceptance criteria
- Spec §6.G.3 Acceptance, every bullet. The Verify record for `a566e00` evidences them.
- Every emitted tool description names no parameter the tool lacks: no left-out `ComponentId`, `ChildList` or
  `Action` prop and no `accessibility.*`.
- A descriptor without `toolDescription` emits its `description`. One with it emits the override, under the
  same 1024-character cap. An empty or whitespace-only `toolDescription` makes the emitter throw, with no
  fallback (orchestrator default, review gate iteration 1).
- `properties` has a null prototype. A descriptor prop named `accessibilityLabel` or `accessibilityDescription`
  makes the emitter throw.
