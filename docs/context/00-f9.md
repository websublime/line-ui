- `npm pack --dry-run` in each of the 8 packages: zero `dist/` files; the tarballs carry `src/`,

## Acceptance criteria (agreed with Miguel)
1. For each of the 8 packages, the tarball the publish path builds contains every `exports` target and no
   `__tests__/`, `tsconfig*.json`, `vite.config.*`, or `*.tsbuildinfo`.
2. No `workspace:` range in any packed manifest; internal dependencies resolve to `^<current version>`.
3. `release` and `snapshot:publish` run in a dry-run mode that packs and checks without touching the registry
   or git tags.
4. `checks.yml` runs the pack guard on every PR.
5. Verify record: `bun run lint`, `bun run build`, `bun test` for the touched scope, `actionlint` on
   `checks.yml`; changeset for the 8 packages (`patch`).

## Decisions (Miguel, 2026-10-02)
- **Bun packs, npm publishes.** A repo script publishes every non-private package outside the Changesets
  `ignore` list whose `name@version` is not in the registry. For each one it runs `bun pm pack`, which
  rewrites `workspace:` and honours `files`, and then `npm publish <tarball>`. Afterwards `changeset tag`
  creates the git tags and prints the `New tag:` lines that `changesets/action@v1` reads. npm stays the
  uploader, so the pipeline keeps npm's token auth today and can adopt OIDC trusted publishing and provenance
  later. Rejected: `bun publish`, which has no OIDC (oven-sh/bun#22423 open) while npm retires 2FA-bypass
  tokens. Also rejected: keeping `changeset publish` behind an in-place `workspace:` rewrite, which mutates
  tracked manifests and copies pnpm's rewrite rules.
- **`files`.** `["dist", "src"]` for the 5 TS-built packages, so the shipped declaration and source maps
  resolve. `["dist"]` for `line-tokens`, `line-colors`, `line-themes`. Rejected: `["dist"]` everywhere,
  which ships maps that point at missing sources.
- **`snapshot:publish` is fixed in F9.** It runs the same script with `--tag canary` and no git tags.
- **Permanent guard.** A script packs every publishable package and fails on a missing `exports` target, a
  forbidden file, or a leftover `workspace:` range. It runs as a `checks.yml` step after the build.
- All of the above lands as `AM-036` (trigger `decision`) in a `docs(spec)` commit before the code.
