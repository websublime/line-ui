## Understanding
- Outcome: `@websublime/line-components/skeleton` registers `<line-skeleton>`, a Static placeholder for content
  that is loading, with a pulse or wave animation, `rect`, `circle` and `text` shapes and multi-line text. It
  carries `agentExposed: true`, with the agent props `shape` and `lines`.
- Stated:
  - PRD §4.1 (`docs/PRD.md:261`): Static, "Placeholder loading indicator with pulse or wave animation".
  - Phase 1 spec row C15: Static, tag `line-skeleton` at `./skeleton`, no role placement, not form-associated,
    `agentExposed: true`, htmx `n/a` expected; the component spec settles busy semantics (R8 §2.2).
  - Miguel's decisions, 2026-11-13, each the recommended option of `0016-skeleton.md`:
    - F1 (a): the placeholder carries no semantics, and the consumer's loading container carries `aria-busy`.
    - F2 (a): `animation="pulse | wave | none"`, default `pulse`, with the keyframes in the component's own CSS.
    - F3 (a): `prefers-reduced-motion: reduce` stops the motion at normal importance, so a consumer can opt back in.
    - F4 (b): two cycles, then rest, through `--line-skeleton-iteration-count: 2`.
    - F5 (a): `shape="rect | circle | text"` plus `lines`.
    - F6 (a): placeholder only, no wrapper mode.
    - F7 (a): agent props `shape` and `lines`.
    - F8 (a): sizing through tokens and `::part(item)`.
  - Miguel, 2026-11-13, on the defaults D1–D21: the consumer chooses the colour through CSS custom properties. The
    fill and the wave band are the public tokens `--line-skeleton-bg` and `--line-skeleton-wave-color`, and D21's
    `--line-gray-surface` is only the default. The spec states the override as a supported contract, with an
    example and a test showing that a consumer value wins. A consumer colour never defeats the D20 forced-colors
    fallback. The other defaults stand as drafted.
  - Miguel, 2026-11-13: Phase 1 spec AM-099, trigger `decision`, adds Skeleton (`0016-skeleton.md` D9) to the
    lists of components that take no host name and no tool accessibility parameters.
- Observed (spec-draft probes P1–P11, Playwright 1.64.0 on chromium, firefox and webkit, happy-dom 20.14.6, htmx
  2.0.11 and 4.0.0, axe 4.14.0; recorded in `0016-skeleton.md` Probes):
  - An empty placeholder adds nothing to the accessibility tree in three engines. `aria-busy` reaches the Chromium
    tree only as an attribute, never through `ElementInternals` (P1).
  - Chromium never resolves a document `@keyframes` from a shadow root, so `--line-animation-pulse` from
    `line-tokens` cannot animate the component. A keyframe name carried in a component token works in all three
    engines (P3).
  - Under forced colors the token fill computes to Canvas and vanishes, while `GrayText` survives (P4).
  - The surface removes the attributes of unset props, so defaults must not depend on reflected attributes (P10).
- Assumed: none beyond defaults D1–D21 as refined above.
