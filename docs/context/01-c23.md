## Understanding
- Outcome: every `LineElement` attaches `ElementInternals` once behind `this[INTERNALS]`, and `FormAssociated`
  reaches the same internals on every delivery path: bundlers, unpkg raw with an import map, and jsDelivr `+esm`.
- Stated:
  - Spec §6.C.2 Changes, Contract and Acceptance, as written before this branch.
  - Miguel's fork answers, 2026-10-26:
    - `[INTERNALS]` visibility, measurement method and changeset bump: orchestrator defaults accepted (the write-back listed them as open).
    - CDN fork: "FormAssociated vindo da raiz" (`FormAssociated` comes from the root) was chosen over three
      alternatives: switching to `Symbol.for('line.internals')`, accepting and documenting the CDN gap, and
      deferring to a P6 probe.
- Observed:
  - jsDelivr `+esm` inlines a file's relative imports into each URL. `line-core@0.1.3/+esm` carries its own
    copy of `./mixins/direction.js` (fetched 2026-10-26). With C23 as first implemented, `line-core/+esm` and
    `line-core/mixins/form-associated/+esm` would each create their own `Symbol('line.internals')`, so
    `this[INTERNALS]` reads `undefined` in `FormAssociated` and the form API throws [INFERENCE: follows from
    the observed inlining; not run end to end].
  - jsDelivr rewrites a self-referencing bare import to the same package's root `+esm` at the same version.
    `preact@10.24.3/hooks/dist/hooks.module.js` has `from "preact"`, and `hooks/+esm` serves
    `from "/npm/preact@10.24.3/+esm"` (fetched 2026-10-26).
  - The unpkg raw path loads `dist/` files as they are, so the shared `dist/internals-*.js` chunk gives one
    Symbol there.
  - `vite.config.shared.mjs:9, :15` makes only `dependencies` and `peerDependencies` external. A package's
    own name is not external today.
- Assumed (orchestrator defaults, for Miguel's review in the PR):
  - The `FormAssociated` implementation moves to `packages/line-core/src/form-associated.ts`. The root
    `src/index.ts` re-exports `FormAssociated` and the `FormAssociatedMembers` type.
  - `src/mixins/form-associated.ts` becomes
    `export { FormAssociated, type FormAssociatedMembers } from '@websublime/line-core'`. The built
    `dist/mixins/form-associated.js` therefore carries a bare self-reference, which jsDelivr maps to the
    root `+esm` and Node and bundlers resolve through `exports`.
  - `vite.config.shared.mjs` adds the manifest's own `name` to the derived externals, so a self-reference
    stays a bare specifier.
  - `packages/line-core/tsconfig.json` stays unchanged. The first default was a `paths` entry that mapped
    `@websublime/line-core` to `./src/index.ts`. The AM-050 probes (Bun 1.4.3, TS 7.0.2) overrode it:
    - Bun applies that package's `paths` at run time, even to the self-references inside `dist/`. A
      consumer test would then load two module graphs.
    - tsc already resolves the self-reference before `dist/` exists, because it maps the `exports` `types`
      target from `outDir` back to `rootDir`.
    - The emitted `.d.ts` keeps the bare specifier.
  - The other `./mixins/*` subpaths stay as they are. They carry no shared runtime identity, and a second
    copy on `+esm` costs bytes only [INFERENCE: the Direction mixin's module-level observer set runs twice].

## Acceptance criteria
- Spec §6.C.2 Acceptance, all of it.
- New from the decision:
  - `FormAssociated` imported from `@websublime/line-core` and from `@websublime/line-core/mixins/form-associated`
    is the same function when resolved through the package's own `exports`, on the built output.
  - A `FormAssociated(LineElement)` element still attaches internals once and keeps its form behaviour in the
    browser tier.
  - P6 adds a check on the `+esm` path: a form-associated element loaded from `line-core/+esm` and
    `line-core/mixins/form-associated/+esm` keeps its form API.
