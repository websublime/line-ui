## Understanding
- Outcome: a Storybook MDX recipe shows consumers how to draw icons in line://ui component slots with CSS mask
  icons, as Lea Verou's "The best way to use icons in Web UIs" (2026-10-11, https://lea.verou.me/blog/2026/icons/)
  and `@nudeui/icons` draw them, and states when not to: the agent path keeps `<line-icon>` and `iconMap`.
- Stated (ledger row, Miguel 2026-10-29):
  - `--icon-*` tokens hold SVG URLs; a masked pseudo-element paints them on an element the consumer puts in a
    component slot.
  - The page states the limits: monochrome glyphs only, container style queries, the WebKit workarounds, and no
    error signal for a missing token, so the agent path keeps `<line-icon>` and `iconMap`.
  - `<line-icon>` gains no mask mode.
- Observed:
  - `@nudeui/icons` 0.0.3 (MIT, Lea Verou, 2026-10-13) ships `icons.css`: `@property --icon-start/--icon-end`
    (non-inheriting), `.icon`/`.icon-start`/`.icon-end` opt-in classes, `@container style(--icon-start|end)` rules
    on `::before`/`::after`, `content: image-set(transparent, var(--icon-…))` so an unset token drops the
    pseudo-element, and the WebKit workarounds for bugs 301609 (zero-duration animation on `::before`/`::after`)
    and 325900 (re-register as inheriting plus a layered reset on descendants), both behind an `@supports`
    WebKit sniff. The article says the 301609 workaround also fixes 320220.
  - Phase 1 slots that take an icon: Button `prefix`/`suffix` (`button.ts:69-70`), IconButton default slot
    (`icon-button.ts:47`), Chip `prefix`/`suffix`/`indicator` (`chip.ts:51-53`), Alert `icon` (`alert.ts:49`),
    Avatar default and `fallback` (`avatar.ts:62-63`). Button spec: the `prefix` and `suffix` zones are the
    slotted light-DOM elements themselves, styled by the consumer (`docs/specs/0002-button.md:140`).
  - The slotted element lives in light DOM, so the document-level system CSS reaches it and its pseudo-element;
    nothing in the component shadow roots changes.
  - Registered properties are ignored in shadow-root styles (csswg-drafts #10541, cited by the article): a
    consumer that renders line://ui inside its own shadow root cannot scope the system there.
  - Line tokens are `--line-*`; the `--icon-*` and `--icon-style-*` names do not collide.
  - A missing token makes `var()` invalid at computed-value time: the pseudo-element disappears silently. The
    agent path raises `line-a2ui-error` (`UNMAPPED_ICON`) for a name missing from `iconMap`
    (`packages/line-genui/src/a2ui/errors.ts:18`); the mask path has no equivalent.
  - Playwright 1.64 browsers all evaluate container style queries: Chromium 156, Firefox 157, WebKit 27.2
    (probe run 2026-11-20).
  - Storybook already self-hosts Lucide under `apps/storybook/public/icons/lucide/` with its LICENSE, and the
    stories make no third-party request (`stories/agent-ui/story-icons.ts:7`).
  - `Recipes/Overview` (`stories/recipes/index.mdx`) covers transports and has a "Related" section for the
    non-transport MCP Apps View page.
- Decided (Miguel, 2026-11-20, each the recommended option):
  1. The icon-system CSS is `@nudeui/icons`, an exact-pinned (`0.0.3`) dev dependency of `apps/storybook`, which
     the recipe's CSF file imports. infra-supervisor adds it to `apps/storybook/package.json` and `bun.lock`;
     `security-reviewer` joins Verify.
  2. The examples cover every Phase 1 icon slot: Button `prefix` and `suffix`, the IconButton default slot, Chip
     `prefix`, `suffix` and `indicator`, and the Alert `icon` slot.
  3. Tests: a Playwright e2e on `storybook-static` in Chromium, Firefox and WebKit asserts that each example's
     pseudo-element paints (computed `mask-image` holds a URL, rendered size above zero), that the missing-token
     example paints nothing, and that axe finds zero violations.
  4. The page is `Recipes/CSS mask icons`, linked from the "Related" section of `Recipes/Overview`.
- Assumed (defaults picked and stated to Miguel):
  - Icon tokens point at the self-hosted Lucide files with document-relative URLs, declared in a `<style>` the

## Acceptance criteria
- `Recipes/CSS mask icons` renders on `storybook-static` with live examples: `--icon-*` tokens on `:root`, and an
  element in each Phase 1 icon slot (Button `prefix`/`suffix`, IconButton default, Chip `prefix`/`suffix`/
  `indicator`, Alert `icon`) painting its glyph through a masked pseudo-element, with `@nudeui/icons` as the system
  CSS.
- The examples show the icon following `currentColor` across variants, a state-driven swap (`:hover`), sizing
  through `--icon-style-size`, and a missing token painting nothing.
- An icon-only IconButton keeps its accessible name from the host `aria-label`.
- The page states every limit in the row: monochrome glyphs only; container style queries and the class
  fallback; WebKit bugs 301609, 320220 and 325900 with their workarounds; no error signal for a missing token, so
  the agent path keeps `<line-icon>` and `iconMap`; and that `<line-icon>` gains no mask mode. It also states the
  shadow-root and relative-URL limits found above.
- `Recipes/Overview` links the page from its "Related" section.
- A new e2e passes in Chromium, Firefox and WebKit: each example paints (computed `mask-image` holds a URL,
  rendered size above zero), the missing-token example paints nothing, and axe finds zero violations on each
  story.
