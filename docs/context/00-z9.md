## Decisions (Miguel, 2026-10-07)
1. **Host.** Cloudflare Pages project `line-ui-storybook`. Rejected: GitHub Pages.
2. **Previews.** A preview deploy per same-repo pull request, plus production on push to `main`. Rejected:
   production-only deploys on push to `main`.
3. **Preview isolation** (review gate, Miguel 2026-10-07). Previews deploy to a Pages project in a separate
   Cloudflare account, with its own token stored in the GitHub environment `storybook-preview`. The production
   token lives in the environment `storybook-production`, whose deployment branch policy allows `main` only.
   Rejected: a required-reviewer approval on every preview run; a single account with the risk recorded.

## Review gate iteration 1 (reviewer, infra-supervisor and security-reviewer lenses)
Orchestrator defaults adopted from the findings, all within decisions 1–3:
- Build and deploy split into two jobs. The build job runs PR code with no secrets and uploads
  `storybook-static` as an artifact; the deploy job never checks out or runs PR code.
- `pull_request` filters on base branch `main`, and previews deploy under `pr-<number>`, so a PR whose head
  branch is `main` cannot reach production and two branches never share an alias.
- The build step builds `./packages/*` before Storybook (AM-029 failure mode).
- The paths filters add the workflow file, `bun.lock` and `.bun-version`.
- Wrangler is an exact devDependency of `apps/storybook`, locked in `bun.lock`, and the deploy job installs it
  from the base commit with lifecycle scripts disabled.
- The job summary prints the branch alias from the `pages-deploy-detailed` output entry.
- The spec carries the Cloudflare bootstrap (accounts, projects with production branch `main`, token
  permissions, environments and secrets) as a prerequisite of the §9.6 check.
- Pull requests from dependency bots are out of scope until a bot is configured.

## Review gate iteration 2 and escalation
