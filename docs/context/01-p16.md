## Understanding

## Threat model
- Today the `Build` step runs vite, postcss, tsc, the CEM analyzer, `emit-catalog.mjs` and
  `validate-contrast.mjs` in the `npm` environment job (`.github/workflows/release.yml:39-40`,
  `.github/workflows/snapshot-deploy.yml:51-52`).
- A compromised build-time dependency runs there with `id-token: write`. It can request an OIDC token and
  exchange it for an npm publish token for any of the 9 packages.
- In `release.yml` the same code can also push branches and tags to the repository, through the persisted
  checkout credentials and `contents: write`, and edit pull requests.
- `--ignore-scripts` (AM-067) closes only the install-time path. AM-068 closed the same gap in `deploy-site.yml`.
- Residual after the split: the `publish` job still runs the locked tooling from `node_modules`
  (`@changesets/cli`, `@changesets/changelog-github`, `changesets/action`) and the publisher. A compromised build
  can still ship malicious `dist` code, and provenance attests it to this workflow. The split does not address
  either.

## Decisions (Miguel, 2026-11-18)
1. Scope covers both `release.yml` and `snapshot-deploy.yml`. The filenames and the environment `npm` stay, so
   the npm trusted publishers, which match on both, still match.
2. A `build` job with `permissions: contents: read` only, no `environment` and no `id-token`.
   - It checks out with `persist-credentials: false`.
   - It sets up Bun from `.bun-version` with `no-cache: true` and Node 24.
   - It runs `bun install --frozen-lockfile --ignore-scripts`, then `bun --filter './packages/*' build`.
   - It uploads `packages/*/dist` and `packages/*/custom-elements.json` with `actions/upload-artifact` v7.0.2.
3. A `publish` job with `needs: build`, `environment: npm` and the workflow's current permissions.
   - It checks out as now, sets up Bun and Node 24, asserts npm/Node, and installs with `--ignore-scripts`.
   - It downloads the artifact with `actions/download-artifact` v8.0.2 and runs no build. Decision 6 sets
     where the artifact lands.
   - In `release.yml` it runs `changesets/action` with the same `version`/`publish` inputs and env.
   - In `snapshot-deploy.yml` it re-runs `bun run snapshot:version` with `GITHUB_TOKEN` at the same commit,
     writes the bootstrap token fallback and runs `bun run snapshot:publish`. The run is deterministic and the
     snapshot guard checks the sha.
   - `scripts/publish.mjs` keeps running checks (a)–(e) on each tarball before upload.
4. "Require main" stays in `snapshot-deploy.yml`. The supervisor picks the placement (below).
5. Merge order: P14, then P16, then a proof canary, then #313, all before 2026-11-20T14:50Z.
6. The artifact lands outside the checkout, and the packer ignores lifecycle scripts (option (b)+(c), decided
   after the Review gate raised it).
   - Threat. A compromised build job controls the artifact, because it runs before the upload step on the same
     runner and can rewrite the files that step uploads [INFERENCE: hosted runners give steps passwordless
     sudo]. Unpacked into `packages/`, a forged `line-genui/package.json` would replace a manifest
     [INFERENCE: `download-artifact` overwrites existing files; not probed]. The publisher would then run
     `bun pm pack` on it, and Bun runs a manifest's `prepack` script, so package code would run in the OIDC job.
   - (b) The `publish` job downloads `package-builds` to `${{ runner.temp }}/package-builds`, as
     `deploy-site.yml` does. A copy step then puts only `<pkg>/dist/` and `<pkg>/custom-elements.json` into
     `packages/<pkg>/`, so manifests, scripts and `src` always come from the checkout. The step is under
     "Copy step" below.
   - (c) `scripts/verify-pack.mjs:93` passes `--ignore-scripts` to `bun pm pack`. The shared staging function
     then never runs `prepack`, `prepare` or `postpack`, for the publisher and for `checks.yml`. No package
     declares any of these scripts (`jq` over `packages/*/package.json`), so no tarball changes.
   - The code changes land in the implement dispatch.

### Rejected
- Carrying the versioned manifests in the artifact. The `publish` job would then trust manifests that the build
  job wrote, and a manifest carries `scripts`, `files` and versions. No build reads the versions, so re-running
  `snapshot:version` gives the same tarballs.
- Splitting `release.yml` only. The `snapshot-deploy.yml` job holds the same OIDC permission, and its trusted
  publishers can publish any of the 9 packages.
- No split. The Medium finding stays open, and #313 would publish the first `line-genui` stable through it.
- (a) Downloading into `packages/`. A forged manifest would replace a checked-out one, and its `prepack` would
  run in the OIDC job.
- (c) alone. Packing would run no lifecycle script, but a forged manifest could still change `files`,
  `version` or `exports` of what ships.

### Supervisor defaults
- "Require main" runs as the first step of both jobs. In `build` it fails a non-`main` dispatch before any
  checkout or build. In `publish` the job that holds OIDC checks the ref itself, so a later edit to `needs`
  cannot drop the check. The `npm` environment policy stays the third layer (AM-038).
- Top-level `permissions: {}` and per-job `permissions`, the `deploy-site.yml` pattern (AM-068). The
  `publish` job lists the former top-level scopes with their comments.
- The `snapshot-deploy.yml` job id `canary` becomes `publish`. Nothing references it, and trusted publishers
  ignore job ids.
- Artifact `package-builds`, `if-no-files-found: error`, `retention-days: 1`. `upload-artifact` roots a
  multi-path upload at the paths' least common ancestor, `packages/`, so each top-level entry is a package
  directory name.
- The `build` job checks out with the default depth, because only `snapshot:version` walks the history.
- The `build` job has no npm/Node assertion, because it publishes nothing.
- Both jobs keep `timeout-minutes: 30`.

## Copy step
The step follows the download in both `publish` jobs.

```yaml
      - name: Copy the build outputs into place  # AM-089: only <pkg>/dist and <pkg>/custom-elements.json; manifests, scripts and src stay from the checkout
        shell: bash                            # -eo pipefail
        env:
          BUILDS: ${{ runner.temp }}/package-builds
        run: |
          shopt -s nullglob dotglob
          fail() { echo "::error::package-builds: $1"; exit 1; }
          [ -z "$(find "$BUILDS" -type l)" ] || fail "symlinks are not allowed"
          for entry in "$BUILDS"/*; do
            pkg=$(basename "$entry")
            [ -d "$entry" ] && [ -f "packages/$pkg/package.json" ] || fail "$pkg is not a package in the checkout"
            [ -d "$entry/dist" ] || fail "$pkg has no dist"
            for item in "$entry"/*; do
              case "$(basename "$item")" in
                dist) ;;
                custom-elements.json) [ -f "$item" ] || fail "$pkg/custom-elements.json is not a file" ;;
                *) fail "unexpected entry $pkg/$(basename "$item")" ;;
              esac
            done
            rm -rf "packages/$pkg/dist"
            cp -R "$entry/dist" "packages/$pkg/dist"
            if [ -f "$entry/custom-elements.json" ]; then cp "$entry/custom-elements.json" "packages/$pkg/"; fi
          done
```

- It fails closed. Any symlink in the artifact, any top-level entry that is not a directory with a
  `packages/<pkg>/package.json` in the checkout, a package entry without `dist`, and any package entry other
  than `dist` and `custom-elements.json` fail the job before the publisher runs.
- `dotglob` makes hidden entries count, so a stray `.DS_Store` fails too. The legitimate upload has none,
  because `upload-artifact` skips hidden files.
- A glob never yields `.` or `..`, and `basename` strips any `/`, so `packages/$pkg` stays inside `packages/`.
- Files inside `dist` are copied as they are. The `publish` job never executes them, because the publisher
  imports only Node built-ins and `scripts/verify-pack.mjs`.
- An empty artifact copies nothing. Check (a) then fails every package before its upload, and
  `if-no-files-found: error` already stops an empty legitimate upload.
- `actionlint -shellcheck=shellcheck` passes. Against scratch artifacts the step copied a valid one, and
  failed on an unknown package directory, a `<pkg>/package.json`, a symlink in `dist`, a hidden top-level or
  package entry, a top-level file, and a package without `dist`.
